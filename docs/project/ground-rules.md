These rules apply to every session; root `AGENTS.md` carries the short form. The [policy hook](/harness/policy-hook.md) and the [git pre-commit hook](/harness/git-hook-and-ci.md) enforce the mechanical parts.

# 1. Matches are measured, never declared

* `./tools/build-and-verify.sh` (full-ROM SHA1) decides whether the project matches; see [build-and-verify](/tools/build-and-verify.md).
* `./build.sh` inside a [decomp environment](/tools/decomp-env.md) decides whether one function matches.
* A function-level match is not enough after changing shared types, data or the Makefile: rebuild the whole ROM.
* Never weaken a check to make a function pass. If a check is wrong, fix it for every input ([changing the harness](/harness/changing-the-harness.md)).

# 2. Protected paths

Never edit these. The policy hook blocks writes to `mariogolf64.sha1`, `asm/` and the vendored tools; the pre-commit hook blocks staging `mariogolf64.sha1`.

* `mariogolf64.sha1`, `baserom.z64`
* `asm/` (generated by Splat; change the C source or project metadata instead)
* Vendored tools: `tools/gcc_kmc`, `tools/kmc-cc`, `tools/decomp-permuter`, `tools/asm-differ`

If a compile needs different behavior, add a per-directory or per-file override in the Makefile's `COMPILER PROFILES` section (see [compiler profiles](/project/compiler-profiles.md)). That is a source change; the checksum verifies it.

Scratch files `ctx.c` and `temp.c` (including `src/ctx.c` and `src/temp.c`) are never read, written or passed as file operands. The policy hook blocks any command that names `temp.c`, and `ctx.c` except as a bare word in a grep pattern, an exclude glob or a commit message.

# 3. Fix the harness, do not route around it

If a tool, script, skill, task prompt or the policy hook is wrong or in your way (bug, false block, missing option, misleading output), fix it generally and keep the fix small. Rules for what evidence a fix needs are in [changing the harness](/harness/changing-the-harness.md). Then return to the original task.

# 4. Commit harness changes separately and immediately

Commit each harness fix on its own, right away, using the steps in [changing the harness](/harness/changing-the-harness.md). Uncommitted work does not survive a failed [nigel](/tools/task-runner.md) candidate, because `reset_command` wipes the tree. Never pass `--no-verify`: the policy hook blocks it, and the pre-commit hook rebuilds and verifies the ROM.

# 5. Agents run scripts, not `make`

The policy hook blocks direct `make` (except `make -s print-cflags SRC=<file>`), direct `python3 -m splat split`, `git commit --no-verify`, and permuter runs without a `timeout` that ends at least 120 seconds before `NIGEL_TIMEOUT_DEADLINE_UNIX`. Use `./tools/build-and-verify.sh` for the whole project and `./build.sh <file>.c` in a decomp environment.
