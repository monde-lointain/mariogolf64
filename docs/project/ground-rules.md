These rules apply to every session. `.omp/RULES.md` carries the short form on every request; this concept is the full statement. The [policy hook](/harness/policy-hook.md) and the [git pre-commit hook](/harness/git-hook-and-ci.md) enforce the mechanical parts.

# 1. Matches are measured, never declared

* `./tools/build-and-verify.sh` (full-ROM SHA1) decides whether the project matches. See [build-and-verify](/tools/build-and-verify.md).
* `./build.sh` inside a [decomp environment](/tools/decomp-env.md) decides whether one function matches.
* A function-level match is not enough after changing shared types, data or the Makefile: rebuild the whole ROM.
* Never weaken a check to make a function pass. If a check is wrong, fix it for every input ([changing the harness](/harness/changing-the-harness.md)).

# 2. Protected paths

Never edit these (the policy hook blocks writes; the pre-commit hook blocks staging `mariogolf64.sha1`):

* `mariogolf64.sha1`, `baserom.z64`
* `asm/` (generated by Splat; change the C source or project metadata instead)
* vendored tools: `tools/gcc_kmc`, `tools/kmc-cc`, `tools/decomp-permuter`, `tools/asm-differ`

If a compile needs different behavior, add a per-directory or per-file override in the Makefile's `COMPILER PROFILES` section (see [compiler profiles](compiler-profiles.md)). That is a source change; the checksum verifies it.

Generated scratch files `ctx.c` and `temp.c` must not be read, written or mentioned in commands.

# 3. Fix the harness, do not route around it

If a tool, script, skill, task prompt or the policy hook is wrong or in your way (bug, false block, missing option, misleading output), fix it generally and keep the fix small. Rules for what evidence a fix needs are in [changing the harness](/harness/changing-the-harness.md). Then return to the original task.

# 4. Commit harness changes separately and immediately

Stage only the harness paths (`git add <paths>`, never `-A`) and use the subject prefix `harness:`. Uncommitted work does not survive a failed [nigel](/tools/task-runner.md) candidate (`reset_command` wipes it). Never pass `--no-verify`; the pre-commit hook rebuilds and verifies the ROM.

# 5. Agents run scripts, not `make`

The policy hook blocks direct `make` (except `make -s print-cflags`), direct `python3 -m splat split`, and permuter runs without a `timeout`. Use `./tools/build-and-verify.sh` for the whole project and `./build.sh <file>.c` in a decomp environment.
