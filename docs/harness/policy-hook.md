`.omp/hooks/pre/mg64-policy.ts` runs on every tool call and returns a block reason. omp loads hooks from `<session cwd>/.omp/hooks/pre/`; decomp environments reach it through their `.omp` symlink, and the repo root is derived from the file's real path, so both behave the same. A running session keeps the hook it loaded: start a new session after editing it. Tests: `bun test ./.omp/hooks/tests/mg64-policy.test.ts`. Changes are [comparison changes](/harness/changing-the-harness.md): a guarded action must stay blocked.

# bash

| Blocked | Because |
|---|---|
| `git commit --no-verify` | The pre-commit rebuild must run ([hook](/harness/git-hook-and-ci.md)). |
| Any `make` except `make [-s\|--no-print-directory] print-cflags [SRC=path]` (redirections such as `2>&1` are ignored) | Use `./tools/build-and-verify.sh` or `./build.sh <file>`. The allowed form only prints flags. |
| `python3 -m splat split` | The build scripts run it. |
| Any mention of `temp.c`. Any mention of `ctx.c`, except a word that names `ctx.c` without reading it: a grep pattern (the first non-option word, when there is no `-e`/`-f`), `--exclude[-dir]=<glob>`, rg `-g '!<glob>'`, find `! -name <x>`, or a `git commit -m` message. A `ctx.c` file operand still blocks (`grep foo -v ctx.c`, `grep -v foo ctx.c`). | Generated decomp.me / m2c scratch files. |
| Shell mutation of `asm/` (`tee`, `rm`, `mv`, `cp`, `sed -i`, redirects, `apply_patch`, `git checkout/restore/clean/apply`, scripted writes) | `asm/` is generated by Splat. |
| Shell writes into `tools/gcc_kmc`, `tools/kmc-cc`, `tools/decomp-permuter`, `tools/asm-differ` | Vendored toolchain. Use a Makefile profile override instead. |
| A permuter run (`tools/permuter`, `tools/decomp-permuter/permuter.py`) not under `timeout`, or whose timeout ends within 120 s of `NIGEL_TIMEOUT_DEADLINE_UNIX` | Runs are unbounded otherwise. A permuter path that is the argument of a read-only command (`cat`, `sed`, `grep`, `git`, ...) is not a run. |

The permuter check tokenizes the command, so a command that mentions `permuter` with an unterminated quote is blocked. Commands that never mention it are not tokenized, which keeps heredocs with unbalanced apostrophes allowed. `&` is a segment boundary and every permuter invocation in a command is checked.

# read, write, edit, ast_edit

* `read`: no `ctx.c` / `temp.c`. Selectors (`:10-20`, `:raw`, `:table`) are stripped first.
* `write`, `edit`, `ast_edit` (`write xd://ast_edit`): no `ctx.c`, `temp.c`, `mariogolf64.sha1`; no path with an `asm` directory component; no vendored-tool path. Targets come from `path`, `_path`, `paths`, hashline `[PATH#TAG]` headers, `MV DEST` lines and `*** Add|Update|Delete File:` / `*** Move to:` lines.
* Paths inside the repo are resolved against the call's cwd with symlinks followed where they exist; paths outside the repo and `scheme://` URLs get only the suffix rules.

# Known limits

* bash rules are textual; the `cwd` parameter is not applied to command heuristics. Because the `make` rule is a regex on the command text, a quoted string containing a separator followed by `make` (for example a grep pattern `'a\|make '`, or a commit message with a line that starts with `make`) is a false positive. Rephrase the text.
* `ast_edit` globs are checked by literal prefix and by suffix on the whole pattern; wildcards or braces before the first `/` are not expanded.
* The `eval` tool's `tool.bash()` bridge emits no `tool_call`, so it is not policed.
* Read-only tools (`grep`, `glob`) are not policed.
* The permuter check matches the path spelling after removing leading `.` and `/`. `../<worktree>/tools/permuter` and absolute paths to the permuter are not recognized, so their runs skip the `timeout` rule.
