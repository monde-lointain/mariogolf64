`mariogolf64.yaml` is the Splat configuration for `baserom.z64`. `make extract` deletes `asm/` and runs Splat, which writes `asm/`, `assets/`, the linker script `mariogolf64.ld` and the auto-generated symbol files from it. Editing procedures: [match-data-segment](/procedures/match-data-segment.md), [match-bss-segment](/procedures/match-bss-segment.md), [match-ultralib-segment](/procedures/match-ultralib-segment.md), [add-asset](/procedures/add-asset.md), [rename-file](/procedures/rename-file.md).

Splat code paths below are in the pinned package `.venv/lib/python3.14/site-packages/splat/` (`splat64[mips]==0.50.1`).

# Options set here

| Option | Value and effect |
|---|---|
| `symbol_addrs_path`, `reloc_addrs_path` | `[symbol_addrs.txt]`, `[reloc_addrs.txt]`. Format: [symbol_addrs.txt format](/reference/symbol-addrs-format.md). |
| `hasm_in_src_path` | `True`. Hand-written `hasm` sources live under `src/`; the name `<dir>/<stem>` maps to `src/<dir>/<stem>.s`. Splat default is `False` (`util/options.py`, `hasm_in_src_path`). |
| `use_legacy_include_asm` | `False`: the first `INCLUDE_ASM` argument is the path and the second is the function name (`segtypes/common/c.py`). |
| `generate_asm_macros_files` | `False`. Splat's default is `True` (`util/options.py`, `generate_asm_macros_files`). The comment in the `options:` block of `mariogolf64.yaml` gives the reason: Splat's template for `include/macro.inc`, `include_asm.h` and `labels.inc` emits `.internal _MACRO_INC_GUARD`, which KMC binutils 2.6 `as` rejects. Those files are maintained by hand. |
| `ld_script_path` | `mariogolf64.ld`, generated by Splat. |
| `compiler: KMC`, `platform: n64`, `gfx_ucode: f3dex2`, `hardware_regs: True`, `mips_abi_float_regs: o32`, `header_encoding: ASCII` | Set in the `options:` block. |

# Segment layout

Segments appear in ROM order:

* `header`, `ipl3` (binary), and `entry` (code, `start: 0x1000`, `vram: 0x80025C00`, containing `[0x1000, hasm, entry/entry]`).
* `main`: `start: 0x1050`, `vram: 0x80025C50`, `follows_vram: entry`, `bss_size: 0x122100`.
* `overlay_0` through `overlay_16`. Overlays 1 and 2 have no segment entries; the `overlay_0` comment says they share its ROM. `overlay_gap` (`vram: 0x80400000`) sits between `overlay_3` and `overlay_4`; its comment says absolute jump targets land there.
* Assets after `overlay_16`: `assets`, `audio_wave_bank`, `audio_wave_table`, `sound_effect_bank`, `assets_D9F450`, `asset_directory`.
* The end marker `- [0x2000000]` closes the list. It is the ROM size; `baserom.z64` is 33554432 bytes.

# Segment keys

| Key | Meaning |
|---|---|
| `vram` | Load address of the segment. Overlays share RAM, so several segments can carry the same `vram`. |
| `follows_vram: <name>` | Resolves to the end symbol of the named segment (`scripts/split.py`, `follows_vram`). A missing name is an error. Splat rejects it together with `vram_class` (`segtypes/segment.py`). `main` sets `vram` and `follows_vram` together. |
| `bss_size` | Size of the segment's bss range. Splat uses it as the segment's end for the last bss entry (see [bss rules](#bss-entries)). |
| `exclusive_ram_id` | Identifier for overlay RAM, `ovl0`, `ovl3`, `ovlgap` and so on. Splat carries it on the parent-segment info (`segtypes/segment.py`, `exclusive_ram_id`). |
| `symbol_name_format` | Pattern for auto-generated names. Default `$VRAM` (`util/options.py`, `symbol_name_format`). `ovl0_$VRAM` gives names such as `func_ovl0_801F4A30` (`util/symbols.py`, `default_name`: `func_`, `D_`, `jtbl_`, and `.L` for labels). |

## bss entries

Form: `- { type: bss, vram: 0x... }`. Splat sizes a bss entry from the next entry's `vram`. The last entry in a segment runs to the parent's `vram_end`, which is `vram + bss_size` (`segtypes/common/group.py`, `segtypes/segment.py`). Setting `bss_size` on an entry whose size can be inferred is an error (`segtypes/common/bss.py`).

* `main` has one raw bss entry, `{ type: bss, vram: 0x800D2930 }`, with no `start:`.
* Each overlay bss entry carries `start:` equal to the ROM start of the next segment. For example, the `overlay_0` bss entry has `start: 0xDE9B0`, and `overlay_3` starts at `0xDE9B0`. Fifteen overlay bss entries follow this form, one in each of `overlay_0` and `overlay_3` through `overlay_16`.
* `{ type: .bss, ... }` is not used.

Splat checks that a child's VRAM lies inside its parent's range (`segtypes/segment.py`).

# Subsegment forms

| Form | Meaning |
|---|---|
| `- [0x1130, c, main/func_80025D30]` | C file `src/main/func_80025D30.c`. Extraction creates it, with one `INCLUDE_ASM` per function, if it does not exist and `create_c_files` is set (default `True`; `segtypes/common/c.py`). |
| `- [0x7E360, hasm, libultra/os/setintmask]` | Hand-written assembly `src/libultra/os/setintmask.s`. |
| `- [0xA2ED0, .data, libmus/aud_sched]` | `.data` owned by the file `libmus/aud_sched`. See [Rules](#rules). |
| `- [0xA5D30, .rodata, main/get_tile_attribute]` | `.rodata` owned by the file `main/get_tile_attribute`. |
| `- [0x91310, data, main_data]` | Raw data with a name, written to `asm/data/main_data.data.s`. |
| `- [0x115D80, data]` | Raw data with no name, written to `asm/data/115D80.data.s`. `[0xA5CE0, rodata]` gives `asm/data/A5CE0.rodata.s`. |
| `- [start, textbin, name]` | Binary text, linked as `.text` (`segtypes/common/textbin.py`). Used for the `rsp/*` entries. |
| `- [start, databin, name]` | Binary data, linked as `.data` (`segtypes/common/databin.py`). Used for the `rsp/*` entries. |
| `- name: sound_effect_bank`, `type: bin`, `start: 0xD9B9C0` | Binary asset written to `assets/sound_effect_bank.bin`. `mariogolf64.ld` defines `sound_effect_bank_ROM_START` and `sound_effect_bank_ROM_END`. |

Not used in this repo: `[start, asm, name]`, `rodatabin`, `.bss` subsegments.

# Rules

* A segment ends where the next begins. Splat errors with `segments out of order` when a segment's start is after the next segment's start (`segtypes/segment.py`).
* A `.data` or `.rodata` entry names the file that owns the data, relative to `src/` and without extension. When that file has code, the name matches its `c`, `hasm`, `textbin` or `databin` subsegment. Data-only files have no subsegment: `libultra/io/vitbl` (`.data`, `src/libultra/io/vitbl.c`), `libkmc/atbl` (`src/libkmc/atbl.c`), `libultra/gu/libm_vals` (`.rodata`, `src/libultra/gu/libm_vals.s`). Renaming a file means changing every entry that names it ([rename-file](/procedures/rename-file.md)).
* Per-function assembly is extracted to `asm/nonmatchings/<segment>/<file>/<function>.s`. The C file holds one `INCLUDE_ASM("asm/nonmatchings/<segment>/<file>", <function>);` per function. Example, in `src/main/func_8002A640.c`: `INCLUDE_ASM("asm/nonmatchings/main/func_8002A640", func_8002A640);`. The one-line rule for `INCLUDE_ASM` is in [File structure](/project/code-quality.md#file-structure).
* After editing the YAML, run [build-and-verify](/tools/build-and-verify.md). Hand edits under `asm/` are lost because `make extract` deletes that directory first.
