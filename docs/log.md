# Docs Update Log

## 2026-10-19
* **Update**: A GCC nested function whose parent is not decompiled yet is matched standalone with the uninitialized static-chain stand-in (`s32 r; volatile s32 unused = r;` or a chain-pointer variant), documented in [registers and scheduling](/reference/kmc-gcc/registers-and-scheduling.md#stack-frames); 18 functions on `dev` already used it with no rule behind it. [decompile-function](/procedures/decompile-function.md) no longer lists the undecompiled parent as a reason to give up: on 2026-10-19, 9 tier-1 failures over 8 functions (`gave_up`, `integration_failed`, `near_miss`) gave it as the reason.
* **Update**: [pipeline metrics](/tools/pipeline-metrics.md) reports matched KB, `$/KB` and `min/KB` per task and model (replacing the `m/h` and `tok/run` columns), and `--since`/`--until` take an ISO datetime, so a harness commit is measured by splitting the window at its commit time. Since 2026-10-19 Haiku tier 1 runs at $0.78/KB and 50 agent-min/KB.
* **Update**: Tier 1's stall limit drops from 10 to 7 ([difficulty ledger](/tools/difficulty-ledger.md)). Replayed over the 369 match logs in the shard worktrees: of 250 matches, 7 needed a plateau of 7 or more attempts (4.6% of matched bytes, which tier 2 retries), while attempts past a 7-attempt plateau were 23.1% of size-weighted attempts (12.9% at 10). Check it with `pipeline_metrics.py --since <commit time>` against `--until` the same time: tier-1 `$/KB` and `min/KB` should fall.
* **Update**: `decompile-unmatched` runs `tools/sync-shard` first, like the other decompile tasks ([task-runner](/tools/task-runner.md)). The policy hook's permuter `timeout` rule recognizes the permuter in another worktree (`../mg64-a/tools/permuter`) and by absolute path; before, those runs skipped it ([policy hook](/harness/policy-hook.md)). `IdleThread`, `MainThread`, `IdleStack` and `nuIdleFunc` drop `allow_duplicated:True`, which Splat only consults for a repeated name or address and neither occurs. [symbol-addrs-format](/reference/symbol-addrs-format.md) states that `undefined_*_auto.txt` are linker inputs (`-T`).
* **Update**: Refactored the bundle for progressive discovery and one owner per fact. Every concept has `type` (one of six), `title`, a one-sentence `description` that each `index.md` copies verbatim, and bundle-absolute links; the rules are in [changing the harness](/harness/changing-the-harness.md#docs-are-part-of-the-harness). The root index routes by task in entry form. Procedures, KMC GCC concepts and tool docs link to the owner of a grammar, flag or rule instead of restating it ([splat-yaml](/reference/splat-yaml.md), [symbol-addrs-format](/reference/symbol-addrs-format.md), [compiler profiles](/project/compiler-profiles.md), [code quality](/project/code-quality.md)). Checked against the implementation: compiler-profile include paths and precedence (`print-cflags`), setup dependencies and make targets, repository layout, `symbol_addrs.txt` attributes and Splat subsegment forms, script flags in the tool catalogs, the nigel task catalog, verify-candidate exit codes, ledger `run_id` source, policy-hook scratch-file rules. Added [shard integration](/tools/shard-integration.md) (`sync-shard`, `integrate-shards`, the `merge-decomp-c` driver) and catalog rows for every undocumented script; [code map](/harness/code-map.md) lists every test and how to run it. Removed log entries for individual function matches.
* **Added**: `tools/progress.py` reports code and data matched in the last build, by bytes and by functions or data symbols, as Game, Libraries and Total rows (`--segments` adds one row per segment). `-o` writes the objdiff `report.json` that decomp.dev reads, and CI now uses it in place of `mapfile_parser objdiff_report`. That report counted 32 MB of binary assets as matched data (93.8%) and the RSP microcode as code. It also counted `entry.s` as unmatched. It replaces `tools/project_status.py`, which left hand-written assembly and data out; `-u` takes over its unmatched-function list. `mapfile_parser` is dropped from `requirements.txt`. See [progress](/tools/progress.md).
* **Update**: Decompile runs cost less per run. Measured on the last 392 sessions: $0.198 per match, 38% of turns after the match, 440 failed relative-path reads, and luna at $1.25 per match against $0.18 for Haiku. Decompile tasks run on Haiku again with shorter prompts. `harvest` records stalls, and tier 1 stops after 10 attempts without progress. `build.sh` prints `Time left` and, on a match, a `NEXT:` line; the run ends when `build-and-verify.sh` succeeds. The environment brief uses absolute paths and asks for copy-and-edit attempts. `.omp/config.yml` spills tool output over 5 KB and disables `todo` and `web_search`. `.omp/RULES.md` is gone (root `AGENTS.md` carries the rules), and the policy hook lets `grep -v ctx.c` and similar exclusions through. See [decompile-function](/procedures/decompile-function.md) and [difficulty ledger](/tools/difficulty-ledger.md).
* **Update**: `tools/integrate-shards` decides what needs review by the paths a commit touches (anything outside `src/`, `include/`, `docs/`, `symbol_addrs.txt`, `mariogolf64.yaml`) instead of its subject. Source-only follow-ups such as a type fix and docs commits integrate after the ROM check; a "Decompile" commit that also edits a tool now stops for review. The policy hook ignores shell redirections on `make print-cflags`, and skill docs link with bundle-absolute paths (a sibling link resolved under `.omp/skills/<name>/`).
* **Update**: `tools/m2ctx.py` removes GCC nested function definitions from the m2c context. m2c's parser rejected the whole context for any owning file with one (for example `src/main/func_8008D100.c`'s `spiral_step`), so bootstrap wrote a blank `base.c`. Enclosing functions and `if`/`while` blocks are kept. Covered by `tools/test_m2ctx.py`.
* **Update**: `dist.py` normalizes every jump-table reference (`jtbl_\w+`, as `objdump.py` and `normalize_asm.py` already did), not only hex-named ones. Overlay tables such as `jtbl_ovl11_8024C738` were scored as register differences against the candidate's `.rodata`. Before/after on `func_ovl11_802436C8`'s `base_1.o`: 99.655% (10 differences) to 100.000% exact ([decomp-env](/tools/decomp-env.md)).
* **Update**: `objdump.py` resolves named globals through `symbol_addrs.txt` as well as auto-named `D_`/`func_` symbols, so a relocation against `g_terrain_tile_cache+0x98E` equals `D_80132D4A+0x944`. Before/after on `func_ovl4_80250FB4`'s probe: 98.462% (20 differences) to 100.000% exact ([decomp-env](/tools/decomp-env.md)).
* **Update**: Overlays (`src/overlay_*`) now compile with `-DF3DEX_GBI_2`, like `src/main`: the overlay display-list builder `func_ovl3_8022A090` matches the ROM only with F3DEX2 opcodes (`E3`/`E1`/`F1`). See [compiler profiles](/project/compiler-profiles.md).
* **Update**: [match-data-segment](/procedures/match-data-segment.md) states that a carved `.rodata` table lands at its ROM offset only when every raw entry after it is also `rodata`-typed, since the linker emits all `.data` before all `.rodata`. Applied to `func_ovl11_802436C8` (`mariogolf64.yaml` `[0x15B8F8, rodata]`, commit `3b0c5b05`): 680 bytes differed before the change and the ROM SHA1 matched after it.
* **Added**: `tools/integrate-shards` cherry-picks shard matches onto `dev` and verifies the ROM after each one. It stops only for commits a person must review. The `tools/merge-decomp-c` merge driver (`.gitattributes`) resolves the extern/`INCLUDE_ASM` conflicts between neighbouring matches. Replaying this run's nine conflicted picks, it reproduced all eight hand resolutions byte for byte and left the type clash conflicted ([task-runner](/tools/task-runner.md)).
* **Update**: [decompile-function](/procedures/decompile-function.md) now places a partial C implementation and its `INCLUDE_ASM` alternative in mutually exclusive `NON_MATCHING` branches; the old example emitted both definitions in a `NON_MATCHING` build.
