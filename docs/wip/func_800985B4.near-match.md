## Why it walls (carve, not codegen)
`jtbl_800D1EE8` = rom 0xAD2E8..0xAD32C (0x44, 17 words). Start 0xAD2E8 is 8-aligned; **trailing edge
0xAD32C is 4-aligned**, and is immediately followed by still-asm sibling strings owned by other
INCLUDE_ASM fns in func_80095A10.c (`D_800D1F2C "            %f"`, `D_800D1F40 "H"`, `D_800D1F44 "G"`,
`"F"`, `"3"`, `"Q"`, ... up to 0xAD3B0=libmus/player). Per memory [[jtbl-carve-both-edge-8align]] a
partial jtbl carve needs BOTH edges 8-aligned + no still-asm rodata interleaved; a 4-aligned trailing
edge pads to 8 and shoves the following sibling string N bytes late = SHA miss. Cannot C-emit the
sibling string to fill the pad because its owner is still asm. Direct analog of the walled
`func_800402F4` jtbl_800CA958 (S219).

## Unblock path
Convert every still-asm sibling that owns rodata between 0xAD32C and the next 8-aligned boundary
(0xAD3B0) to C in the SAME slice, so their strings emit as literals and the region packs contiguously.
That is most of func_80095A10.c (many FP-heavy siblings) = a whole-file slice, not a leaf. Revisit
when func_80095A10.c is taken as a full-file increment.
