## Root cause (reorg.c, S213 compiler-source dive)
`fill_slots_from_thread` (reorg.c:3374) fills the delay with the fall-through's
first insn iff: (a) its dest reg is NOT live at the join, (b) NOT may_trap_p,
(c) own_fallthrough (single predecessor). The slot stays NOP only if one flips:
(a) dest live at join (non-void return), (b) first insn is a load/deref/trap,
(c) a CODE_LABEL heads the block. These fns are void + single-pred + first insn
materializes a CONSTANT (`li`/`sll` into a dead-at-return scratch) -> all three
"fill" conditions hold -> reorg ALWAYS fills. Every byte-preserving C spelling
that flips a condition changes other bytes (non-void adds an epilogue insn,
load-value changes `li`->`lbu`, extra control flow). No byte-identical C exists.

CONTRAST: matched siblings that STORE A PARAMETER keep the NOP for free (the
deref store is the first insn = route (b)). And activate_texture_anim_slot
(S213, BANKED) FILLS its beq delay because the constant `li v1,4` is emitted
first and reorg legally steals it -- there the fill IS the target, matched by
putting the value materialization before the address (`u8 val=4;` first).
