## Root cause (gcc-2.7.2, cited)
`config/mips/mips.h` `GO_IF_LEGITIMATE_ADDRESS` **:2318-2349** accepts `(plus reg CONSTANT_ADDRESS)`
as a legitimate address: gcc folds `%lo(sym)` into the mem displacement over an index/base reg and
emits a fresh `lui %hi(sym)` per access. The in-source comment **mips.h:2325-2335** is explicit:
"the assembler can use $r1 to load just the high 16 bits ... whereas the compiler generates a 4
instruction sequence. On the other hand, **CSE is not as effective**. It would be a win to generate
the lui directly, but the MIPS assembler does not have syntax to generate the appropriate relocation."
So from faithful C referencing these as file-scope `D_` globals, gcc never CSE-shares the `%hi(sym)`
into one base register held across the nearby-symbol accesses; the ROM's opposite choice
(materialize full `&D_801B60BB`, reach `D_801B6090` via numeric `-0x2B` displacement, hold
`&D_801B6090` across the inner loop) is an addressing-mode + allocno-coloring artifact.
