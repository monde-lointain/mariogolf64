## Semantics
20-byte base-28 code/password generator. Confirmed by the sibling DECODER `func_80098D70` (walks the
28-entry alphabet `D_800C73F0[28]`) and the bit-reverse checksum `func_80098CA0`. Copies a 16-byte
record from `arg0`, clamps 4 fields, encodes 3 numbers as 5 base-28 digits each into `digits[0..14]`
(unsigned `%28` -> ÷7 magic 0x24924925), then a 2-pass checksum mix writes `digits[0..4]`,`[5..9]`
and `digits[15..19]` (signed `%28` -> ÷9 magic 0x92492493). A `rand()%4600` feeds the 3rd number.
Ends `func_80098CD8(digits, arg1, 0x14, 0)`.

Record layout (`Struct990D0`, 0x10): b0/b1/b2/b3 @0-3 (b3 clamp <0x12), h4 @4 (u16 clamp, read signed
`lh` in loop3), w8 @8 (dec + lower-clamp 0x1A5DF), bC @0xC (clamp <0x64).

## Cracks that WORKED (exact-count + body-clean levers)
1. **Exact count (the 2 missing instrs = `sw $s2`/`lw $s2`):** `Struct990D0* r = &rec;` and read
   loop2/loop3 fields via `r->bC/w8/b3/h4`. Forces `&rec` into the 3rd callee-saved reg ($s1),
   giving the ROM roles i->$s0, &rec->$s1, arg1->$s2. Supplies the save/restore pair automatically.
2. **loop3 `j=4` AFTER the `rand()` val-compute:** the down-counter was live across `rand` ->
   callee-saved; moving it demotes j to a caller-saved temp ($a3) AND restores the ROM's unfilled
   `jal rand; nop` delay slot (gcc no longer has a value to fill it).
3. **Digit-loop coloring (cmpfn 156->108):** split the single reused `p` into per-loop `w1/w2/w3`.
   greg dump proved the shared-`p` web conflicted with hard-reg $a2 (held by the checksum pointers),
   forcing the digit pointer off $a2. After the split the digit loops match {p=$a2,j=$a3,magic=$t0}.
4. **`s16 h4` + `(u16)rec.h4` clamp cast:** loop3 reads `rec.h4` as signed `lh` (ROM) while the clamp
   stays unsigned `lhu`+`andi`+`sltiu`.
5. **Inline checksum-loop1 2nd mod** `*q = (*q + *hi) % 28;` (drop the `sum` temp): coalesces the mod
   result into the dividend reg; both checksum BODIES then match (108->82).
6. **Frame 0x50 (dead-frame):** `s32 unused[2]` as the FIRST local -> reserves the 8 dead bytes the
   ROM keeps at sp+0x10-0x18, so frame=0x50 with digits@0x18, rec@0x30 all matching. No added
   instruction (gcc 2.7.2 reserves the unreferenced-array slot). See memory
   [[pure-dead-frame-clean-crack]]. HIDDEN by cmpfn's immediate normalization — a frame-size
   mismatch is invisible in the cmpfn diff; always cross-check `addiu sp` vs the ROM.
