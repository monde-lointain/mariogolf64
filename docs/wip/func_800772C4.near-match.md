## What it is (fully RE'd)
`s32 func_800772C4(f32 *a0, s32 a1, s32 a2, f32 *a3)` — spline-segment stepper.
a0 = Vec3f buffer (stride 0xC), a1 = slot index, a2 = selector, a3 = f32[3] out.
Shared globals: `D_800C45D0` (s32 current-segment index), `D_800C45D4` (s32
substep counter). Scratch f32 pool `D_800E1D20..D_800E1D54` (current point, the
two control points reloaded per segment, step increment `D_800E1D4C=1/steps`,
step accumulator `D_800E1D48`, `D_800E1D50`=steps, `D_800E1D54`=speed).

Behavior: on the final slot, copy the last point out + reset globals, return 1.
On segment start (D0==0 && D4==0), the `a2` selector picks (speed,steps) from 9
cases (12/14/18/24/28/216/34/48/416 -> speed 1..4, steps 2..16) via a compiler
balanced-BST `switch` (median pivot 0x1C, NO jtbl; sparse values force the tree;
cases 216/416 tail-merge on the shared `16.0`). Then per-substep: lerp+truncate
each of the 3 coords `Dxx += (f32)(s32)((base+(hi-base)*t - Dxx)*inv)`, emit to
a3, advance the step accumulator; when `steps <= (f32)counter`, reload the next
segment's control points and advance the segment index.

## Best body
`nonmatchings/func_800772C4/base.c` (on disk) — semantically exact, control flow

## Why it walls (14 rows, one class)
1. ROM copies the buffer base `a0 -> $t0` at entry (`addu t0,a0,zero`) and homes
   it in `t0` everywhere; the build keeps it in `$a0`. A local `f32 *buf=a0;`
   copy coalesces away at -O2.
2. ROM address-CSEs two scratch globals (`&D_800E1D30 -> $a1`, `&D_800E1D20 ->
   $v1`, persistent across the math + reload blocks); the build re-materializes
   each `%hi/%lo`.
3. The above flips the post-reload scheduler between sequential (`$f0`-reuse
   load/store pairs) and pipelined (`$f2/$f4/$f6/$f8/$f10`) load emission, adding
   ~6 rows, plus a consequent FP-register renumbering across the math block.
