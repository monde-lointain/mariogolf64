## Parallel compiler-source investigation

Four read-only slices inspected expansion/CSE, allocation, CFG/reorg, and the
GCC/GAS boundary. The parent alone compiled four proposed source structures,
serially, under the unchanged host profile. No compiler or assembler sources
were modified.

**Allocation constraint.** `global.c:614-729,1317-1350` translates local
assignments through `reg_renumber` into global hard-register conflicts.
`global.c:848-855,906-925,963-986,1001-1039` excludes those registers before
applying preferences. This is a hard conflict, not a priority tie. The
baseline result is live while local guard scratch occupies `$v0`.

**Expansion and CSE are distinct gates.** In the parameter-accumulator probe,
RTL insns 14/16 initially set a fresh comparison pseudo and copy it to the
parameter pseudo. CSE removes that copy and makes the parameter pseudo the
comparison destination; combine folds the comparison to `a0 <= 7679`.
Nevertheless, `parameter-accumulator.greg:4-14` assigns that accumulator to
`$a0`, with conflicts including hard register 2. Thus direct destination
formation at initial RTL is not necessary: CSE repairs it, but allocation
still fails. Relevant lowering: `config/mips/mips.c:1735-1810,1840-1880`,
`expr.c:5678-5707,5717` onward.

**Assembler boundary.** Inspected
`~/projects/tools/mips-binutils-2.6/gas/config/tc-mips.c:1268-1291,1523-1568,1667-1671,6815-6826`
and GCC `config/mips/mips.c:3596-3636`, `mips.h:3311-3314`.
The third branch is outside GCC's `.set noreorder` sequence; GAS cannot move
the preceding comparison into its dependent branch's slot and inserts a
`nop`. GCC explicitly emits the final return copy inside `.set noreorder`.
GAS alias expansion and hazard handling do not create the `$a2` result.
No evidence supports changing compiler profiles or assembler flags.

### Initial strategy conclusion

The first fan-out established that the next lever must remove the hard-2
conflict while preserving the initialized-zero result, shared epilogue, and
`andi 2; sltu` tail. Threaded predicates demonstrated CSE destination
coalescing, but did not solve the remaining scratch overlap. The following
post-join lifetime experiment resolves that constraint.

## Resolution: post-join CSE lifetimes

The decisive rule is in `cse.c:830-857`, not allocation priority.
`make_regs_eqv` prefers a pseudo whose first use precedes the current CSE
block or whose last use extends beyond it, provided its last use is later
than the current canonical register's. `cse.c:7440-7476` then rewrites a
preceding producer into that canonical destination.

Reusing parameters/locals without crossing the common join did not satisfy
the rule: the paired `parameter-scratch` experiment still scores 475 and is
byte-identical to the earlier separate-scratch object. Its immutable pair is
`measurements/b2fec3418460e5c2537a022aaeaac39bbef2c869240728dc5dbbc06b0afaac38.{c,json}`.

The matching C explicitly loads the camera into `bound`, reuses `arg0` for
the negative constant and later global load, and assigns each guard predicate
back into `bound`. Crucially, after the common join it returns through:

```c
arg0 = result;
bound = arg0;
return bound;
```

Those genuine post-join uses extend both scratch variables beyond the first
CSE block. In `postjoin-copies.cse`, insns 30 and 46 now write both comparisons
directly into pseudo 75 (`bound`). The camera, constant, and threshold load
also use the intended persistent scratch pseudos. Later copy optimization
removes the return chain; no extra machine instruction remains.

`postjoin-copies.greg:4-14` records:

- Result pseudo 74 no longer conflicts with hard register 2, has preference
  2, and is allocated `$v0`.
- Scratch pseudo 75 is allocated `$v1`; parameter/scratch pseudo 72 gets `$a0`.
- Final bit-test locals can still use `$v0`, because the old result is dead
  on that successful path.

No inline assembly, explicit register binding, volatile access, undefined
read, compiler change, or profile override was introduced.
