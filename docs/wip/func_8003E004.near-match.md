# func_8003E004 — near-match (S204 -> S235 -> S318, CARRIED)

`src/main/func_8003DFD0.c`, 0x310 / 196 instructions, the file's last `INCLUDE_ASM` stub. Banking it

## Measured (rows as of S318)

Body: `nonmatchings/func_8003E004/s318-body-196-88rows.c` (the S204 `base.c` with two edits).

- **196 of 196 instructions at the ROM's exact `-0x140` frame**, mnemonic multiset matching.
- **88 `cmpfn` rows.**
- The S204/S235 replay is **194 of 196**, not "structurally 100%": it is two `nop`s short. Both are
  the load-use slot after an `mtc1` — the ROM's `ldc1` of the `D_800CA8E8` / `D_800CA8F0` pool
  constant lands in `$f4`, the same scratch the following `mtc1` writes, so the anti-dependency
  pins `sub.d`/`add.d` ahead of the `mtc1` and the slot cannot be filled. The build put the constant
  in `$f22`/`$f0`, freeing the scheduler to fill both slots.
- **The fix is to hoist the angle out of the `sinf()` argument**: `ang_lo = (f32)((t = (f64)base) -
  D_800CA8E8);` and `ang_hi = (f32)(t = t + D_800CA8F0);` as their own statements ahead of the
  `a->x` / `b->x` assignments. That restores both `nop`s and the exact count.
- Residual, in three clusters: (1) the preheader's loop-invariant constant order (the ROM emits the
  `8533.0f` and `46.079998f` materialisations and `li 9` before the `base_pos` pointer; the build
  emits the pointer first); (2) the angle chain's *block*: hoisting it out of the call argument also
  moves it ahead of the first `jal sinf`, where the ROM computes it between the two calls; (3) the
  `s1`/`s2` swap the S235 verdict named — the ROM holds `i` in `$s1` and the `a` row pointer in
  `$s2`, the build the reverse.

## S320 re-open (stretch slot) — carried; the permuter run the checklist asked for is now spent

- **Base reproduces**: `nonmatchings/func_8003E004/s318-body-196-88rows.c` is **196/196 at the ROM's
  `-0x140` frame, 88 `cmpfn` rows (cmpfn as of S320)**. Copy kept as
  `nonmatchings/func_8003E004/s320-body-196-88rows.c`.
- **Cluster (1) is re-classified: it is a within-preheader *scheduling* order, not a hoist order.**
  The ROM materialises the two FP constants and `li 9` before `addiu s3,v1,-0x28` (`base_pos`); the
  build emits `base_pos` first. `loop.c` inserts each hoisted movable immediately before
  `loop_start`, i.e. after everything already in the preheader, so no hoist-order edit can put the
  constants ahead of a `base_pos` that the source computes before the loop. Two ways out, both
  refuted: computing `base_pos` inside the loop body (so it hoists *after* the constants in body
  order) costs an instruction — **195/196** — because with `anglep` dead outside the loop gcc folds
  the address into its own `lui`/`addiu` instead of reusing the pre-loop `lui` the ROM shares; and an
  empty `__asm__ __volatile__("")` before the `base_pos` statement reads **98 rows**. The preheader
  is one basic block, so what remains is a `sched` question about two independent, consumer-free
  computations.
- **Checklist item 5 is now spent: the permuter has been run from the frame-correct 196/196 body**
  (`nonmatchings/func_8003E004-4`, 15 min, `-j4 --best-only`, `permuter_settings_main.toml`). Base
  1810 -> best **1505**, no zero. **The deliverable is negative and it is worth recording:** every
  candidate it favours is **198 instructions at frame `-0x148`** — the scorer tolerates extra
  instructions (the known asm-differ failure mode), so it is optimising a body two instructions
  longer than the ROM. Re-measured in-tree, its three levers (a pre-loop `f64` temp for
  `D_800CA8F0`, an `f32` temp for `sinf(base) * i`, and capturing `cosf(base)` in an assignment
  expression) give **198/196, 380 rows** together, and the `D_800CA8F0` hoist alone gives the same.
  So the S235 verdict's replacement is not "the permuter was never run from the right body" but
  "it was, and it walks off the exact instruction count".

  3750, so i needs 16 refs or a needs 9) stands.
