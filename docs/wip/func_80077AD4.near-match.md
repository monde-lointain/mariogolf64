## What it is (fully RE'd)
Cubic finite-difference interpolation. `f32 func_80077AD4(f32 *arg0, f32 arg1)`
(the `f32` second arg is passed in integer `$a1`, `mtc1 a1,ft1` — KMC o32 ABI for
a float arg after a pointer arg; matched). idx = (s32)arg1; loads a stack array
`f32 v[3]` = arg0[idx..idx+2]; frac = arg1 - idx; four integer temps
ia0=(s32)v[0], ia1=(s32)v[1], d0=(s32)(v[1]-v[0]), d1=(s32)(v[2]-v[1]); returns
`c3*frac^3 + c2*frac^2 + d0*frac + ia0` with c3=(ia0-ia1)*2+d0+d1,
c2=ia1*3-ia0*3-d0*2-d1. NOT Horner (ROM muls each coeff by frac separately).

## Best body
The array form (kept in `nonmatchings/func_80077AD4/base.c`) reproduces:

  CSE-forwarded to registers), and

## Why it walls
The residual is a pervasive REGISTER-ASSIGNMENT permutation of the 4 integer
temps + one scheduling hoist, none reachable from faithful C:
- ROM allocates ia0->$a2, ia1->$a0, d0->$a1, d1->$a3; the build lands them
  ia0->$a1, ia1->$v1, d0->$a0, d1->$a2 (rows 18-28, the mfc1 destinations).
- ROM HOISTS `ia0*3` (`sll v1,a2,1; addu v1,v1,a2`) into the truncation phase
  (rows 23-24); the build materializes it inside the c2 term.
- ROM computes float `d1=v[2]-v[1]` LATE (after the ia0/ia1 truncations, row 22);
  the build schedules it early.

## Levers tried (all regressed to 0.50 or held 0.62)
- scalar vs `f32 v[3]` array (array = frame + stores, needed for 0.62 vs -0.02).
- reorder df0/df1 float-sub computation to match ROM dependency order -> 0.50.
- `(ia1-ia0)*3` vs `(ia1*3)-(ia0*3)` for c2 -> 0.50.
- reorder ia0/ia1/d0/d1 declaration+compute order -> 0.50.
Best stays the m2c-natural order (0.62). Permuter N/A (< 0.97 threshold).
