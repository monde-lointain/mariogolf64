# func_8004DC44 WIP — dead-frame reload-artifact regalloc wall (S173 compiler-source dive)

`src/main/print_string_at_grid.c` lone remaining stub (0x8004DC44, 300B/75 insns). Console-scroll

running offsets src/dst, `src %= 4800` per row. `void func(void)` (single caller 0x80030FE0 passes no
args, bare-nop delay slot). Classical, no upstream, no rodata carve; all refs placed `D_`/`flag`

## IMPROVED SEED (vA) — supersedes the S172 carried seed
Operations now match the ROM **100%** (seq 55/75 structural). The S172 carried seed was MISSING the
base-hoist fix (subagent-verified) — that is why the prior 31k-iter permuter run plateaued.

```c
void func_8004DC44(void) {
    s32 nrows = D_800BFEE8;
    s32 src = ((D_800DC6D0 / 40 - nrows) * 40 + 4800) % 4800;
    s32 dst = 1200 - (nrows + 3) * 40;
    s32 row = 0;
    if (nrows <= 0) return;
    {
        u8 *grid = D_800DAF60;
        u8 *ring = D_800DB410;
    outer:
        { s32 i; for (i = 0; i < 40; i++) { grid[dst] = ring[src]; src++; dst++; } }
        row++; src %= 4800;
        if (row < D_800BFEE8) goto outer;
    }
}
```
Seed levers (all verified against KMC gcc): (1) **pre-declare the two array bases as pointer vars
before the `outer:` label** — goto-loops are invisible to loop.c (no LICM), so program-order is the
only base-hoist mechanism; this lands `la`/`lui+addiu` once before the loop, held in regs, matching
the ROM (subagent: loop.c `find_and_verify_loops` registers loops ONLY on `NOTE_INSN_LOOP_BEG` notes,
emitted only by real for/while/do). (2) **bases declared AFTER the `if(nrows<=0)return` guard** (so
they hoist to the preheader like the ROM, not before the guard). (3) **structured inner `for`**
(gives loop.c strength-reduction → the pointer-IV pattern the ROM has). (4) outer loop MUST stay
`goto` (a structured outer loop hoists the `%4800` magic into a held reg — WRONG; ROM rematerializes
it; loop.c cannot selectively hoist SYMBOL_REF bases while declining the CONST_INT magic — `invariant_p`
treats them identically).

     original source uses a divide/reciprocal expression shape not equivalent to any tried reordering,

     does NOT reproduce the ROM — an unexplained gap = a mechanism/preference not captured, or a

## S174 FINAL — verdict CORRECTED: FLIPPABLE-IN-ISOLATION, not "irreducible"

The "irreducible" framing above (and in S173) is **WRONG**. A later-in-S174 cross-project sweep (8 KMC
gcc 2.7.2 decomps: marioparty1/2/3, snowboardkids2, drmario64, hm64, puzzleleague64) + RTL pass dumps
(`-dl`/`-dg`/`-ds`) + 2 more compiler-source subagents (SA-A `local-alloc.c`, SA-B `sched.c`/`reload1.c`)
established the true mechanism:

- **`return D_800DC6D0/40` reproduces the ROM's `/40` divide BYTE-FOR-BYTE** (dividend→`$v0`, magic→`$v1`).
  So the swap is flippable; S173's "unrecoverable from asm" was over-scoped.
- **Mechanism:** dividend→`$v0` requires a physical **reg-2 SET** (a `(set $v0 …)` return/call copy)
  adjacent to the divide chain. That records a `$v0` copy-suggestion (`combine_regs`, local-alloc.c
  1824-1838) on the chain's qty (dividend/sign/quotient are unioned into one qty via the in-place
  `sra`/`subu`, 1840-1885), and the **suggestion pass** (1466-1477) pins it to `$v0` before the
  life-priority general pass. ANY arithmetic on the quotient before it reaches `$v0` breaks this.
- **Why func_8004DC44 still can't match:** it is a **void, callless, returnless leaf whose quotient feeds
  arithmetic then a loop-carried store** → it emits NO reg-2 mention → the chain falls to the general
  pass where the 2-insn magic (shortest life) deterministically takes `$v0`. Verified void/callless/
  returnless (0 `jal`, `jr` with no `$v0` setup).
- **Every faithful lever exhausted, all magic→`$v0`:** 24 control-flow × src combos (goto/for/while/
  do-while outer × for/while/goto inner), multi-term dividends, all associativity, the sched1 lifetime
  lever (`life_magic > ⅔·life_dividend` — the loop-setup pressure sinks the magic to life ~3 in every
  form; life_dividend stuck at 18), memcpy (inlines as `lwl/lwr` word moves, not the ROM's `lbu/sb`),
  m2c (independent decompile = plain global divide, no hidden provenance).
- **`register asm("$2")` hack:** DOES force dividend→`$v0` (28 diffs, down from vA's 38), but is
  non-idiomatic (shows as `asm` in the decompile) AND incomplete — leaves the quotient intermediate in
  `v1` where the ROM uses `a3`, and the dead frame still absent. Not a faithful match.

**Corrected verdict:** the `/40` divide is flippable-in-isolation, but this void-loop-fed leaf is
deterministically magic→`$v0` by local-alloc; the ROM's coordinated dividend-`$v0` + quotient-`a3` +
dead-frame is a sched1/pressure state the toolchain doesn't produce from any source-equivalent void-leaf
input. Playbook: `#signed-divide-const-v0v1-quotient-destination`. Carry kept RETRYABLE (needs a
genuinely new mechanism; do NOT re-run the same-fn permuter/dive — ~430k iters exhausted).

### Probe 2 — does the plain `register` keyword produce a closer match? DEFINITIVE NO (source-grounded)
Distinct from the `register asm("$2")` hard-reg hack (S174). Tested the plain `register` storage-class
hint. **Empirical (controlled):** plain `s32 seed` vs `register s32 seed` at identical structure →
`.text` is **BYTE-IDENTICAL** (only ELF symtab metadata at file-off 0x3A4 differs); both keep
`mult v1,v0`; both 38-diff vs ROM. So `register` is a **zero-`.text`-effect no-op** for the match.
**Compiler-source (3 subagents on mips-gcc-2.7.2), why:**
- **Propagation (SA-1):** plain `register` sets `DECL_REGISTER=1` (c-decl.c:4993) + `REG_USERVAR_P=1`
  (stmt.c:3390) — but at `-O2` `obey_regdecls==0`, so `DECL_REGISTER` is IGNORED (stmt.c:3364), and a
  plain local ALSO gets `REG_USERVAR_P=1`. No hard reg is chosen without an `asm(...)` spec (that path
  is `toplev.c:2601` → `make_decl_rtl` → `varasm.c:536`, `asmspec != 0` guarded). MIPS defines no
  `SMALL_REGISTER_CLASSES`, compiling out even the hard-reg `REG_USERVAR_P` checks in combine/reload1.
- **Allocation (SA-2, grep-proof):** `REG_USERVAR_P` has **0 hits** in `local-alloc.c` and `global.c`.
  The allocation priority (`qty_compare`, local-alloc.c:1578-1623) is purely
  `n_refs·log2(n_refs)·size/(death−birth)` — no user-var term; the short-lived magic wins by that
  formula. `find_free_reg` scans ascending regno (no `REG_ALLOC_ORDER` on MIPS). So `register` cannot
  reorder the dividend-vs-magic allocno.
- **Provenance (SA-3):** the register flag DOES survive into the multiply's dividend operand
  (`force_reg` returns a REG unchanged, explow.c:638; no `PROMOTE_MODE` on MIPS so no stripping SUBREG;
  the magic is always a fresh `copy_to_mode_reg` pseudo, optabs.c:474) — but per SA-2 nothing in
  allocation reads the flag, so reaching the dividend is moot.

**Net:** the plain `register` keyword changes no `.text` and cannot flip the divide; the `register
asm("$2")` hard-reg binding flips the dividend but is unfaithful AND incomplete (quotient→`$v1`, ROM
wants fresh `$a3`). Both ruled out with compiler-source proof.

**S175 verdict:** carry re-affirmed, characterization sharpened. New project-best 13530/13235 (frame +
schedule + ops all match ROM; only the `/40` divide-register cascade remains). The residual is a single
coordinated local-alloc coloring decision (dividend→`$v0` + quotient→fresh-`$a3` + dead-frame) that no
faithful source construct — control-flow, association, `register`, or schedule lever — reproduces in a
void/callless/returnless loop-fed leaf. Playbook: `#signed-divide-const-v0v1-quotient-destination` +
`#dead-frame-reload-artifact-regalloc-wall`. Retryable only with a genuinely new mechanism; the
permuter-reseed and `register`-keyword angles are now both spent.
Best candidates preserved: `output-13530-1/` (cleanest), `output-13235-*/`. base.c restored to vA.
