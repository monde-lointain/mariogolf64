## IMPROVED SEED (vA) — supersedes the S172 carried seed
Operations now match the ROM **100%** (seq 55/75 structural). The S172 carried seed was MISSING the
base-hoist fix (subagent-verified) — that is why the prior 31k-iter permuter run plateaued.

```c
void func_8004DC44(void) {
    s32 nrows = D_800BFEE8;
    s32 src = ((D_800DC6D0 / 40 - nrows) * 40 + 4800) % 4800;
    s32 dst = 1200 - (nrows + 3) * 40;
    s32 row = 0;
    if (nrows <= 0) return;
    {
        u8 *grid = D_800DAF60;
        u8 *ring = D_800DB410;
    outer:
        { s32 i; for (i = 0; i < 40; i++) { grid[dst] = ring[src]; src++; dst++; } }
        row++; src %= 4800;
        if (row < D_800BFEE8) goto outer;
    }
}
```
Seed levers (all verified against KMC gcc): (1) **pre-declare the two array bases as pointer vars
before the `outer:` label** — goto-loops are invisible to loop.c (no LICM), so program-order is the
only base-hoist mechanism; this lands `la`/`lui+addiu` once before the loop, held in regs, matching
the ROM (subagent: loop.c `find_and_verify_loops` registers loops ONLY on `NOTE_INSN_LOOP_BEG` notes,
emitted only by real for/while/do). (2) **bases declared AFTER the `if(nrows<=0)return` guard** (so
they hoist to the preheader like the ROM, not before the guard). (3) **structured inner `for`**
(gives loop.c strength-reduction → the pointer-IV pattern the ROM has). (4) outer loop MUST stay
`goto` (a structured outer loop hoists the `%4800` magic into a held reg — WRONG; ROM rematerializes
it; loop.c cannot selectively hoist SYMBOL_REF bases while declining the CONST_INT magic — `invariant_p`
treats them identically).

## THE RESIDUAL = pure register allocation (2 items, both compiler artifacts)
Every OPERATION matches. Only two register-assignment differences remain:

1. **Dead 8-byte frame** (`addiu sp,-8`/`+8`, zero stack access) = ONE greedy reload spill of a
   preamble temp, rounded 4→8 by `MIPS_STACK_ALIGN` (mips.h:2063). REACHABLE: structured outer loops
   produce it (via magic-hoist pressure, wrong reason), and the **permuter found a frame-bearing
   75-insn candidate from this seed** (score 14450, frame at the exact ROM position) by extracting the
   src computation into an inline helper. Frame and the goto/structured choice are ORTHOGONAL (by
   reload time the loop history is gone; just BBs + conflict graph).

2. **`v0<->v1` swap in the signed-divide-by-40** (THE true wall). ROM: dividend→$v0, magic
   0x66666667→$v1. Every build (~35 variants + 275k permuter iters): dividend→$v1, magic→$v0. The swap
   cascades to ~32 of 75 instructions. NOT source-reachable:
   - `expmed.c:2820` force_reg's the dividend first; `expand_mult_highpart` creates the highpart pseudo
     (`expmed.c:2582`) then `optabs.c:474` copy_to_mode_reg's the magic into a LATER pseudo. Fixed order.
   - `local-alloc.c` priority (`qty_compare_1`, life-dominated, deliberately matched to global.c:594):
     `pri = floor_log2(refs)*refs*size/life*10000`. Dividend (refs 3, life 18) = **1666**; magic
     (refs 2, life 3) = **6666**. The magic's TINY live range gives it 4x priority → allocated first →
     `find_free_reg` (ascending scan, no REG_ALLOC_ORDER on MIPS) hands it $v0.
   - Tested: +1..6 extra dividend refs (life grew in lockstep, ratio worsened); explicit
     reciprocal-multiply form (`(s64)x*0x66666667>>32`, real `mult`, changed dividend reg to $a0 but
     magic still $v0); ~35 control-flow/reorder/interleave/tie-break variants. Never flips.
   - The ROM assigns dividend→$v0 with an OUTWARDLY IDENTICAL instruction sequence — implies the
     original source uses a divide/reciprocal expression shape not equivalent to any tried reordering,
     unrecoverable from the asm. (The subagent model predicts magic→$v0 and reproduces MY build; it
     does NOT reproduce the ROM — an unexplained gap = a mechanism/preference not captured, or a
     different source shape.)
