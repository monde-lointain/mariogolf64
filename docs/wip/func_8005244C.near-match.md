## Attributed

**S316 broke the mutual exclusion S261 recorded for this class.** The earlier verdict — that
`{-0x8(s4) addressing off a held base}` and `{the value read in the preheader}` cannot hold together
in gcc 2.7.2 — is wrong. Each premise had a lever, and both are now byte-confirmed here:

1. **The held base comes from the array-element spelling, not from a pointer local.**
   `extern s32 D_801B60A0[];` with `D_801B60A0[0]` for the flag word and `D_801B60A0[-2]` for the
   bound materializes `la s4,D_801B60A0` and reads both off it. A pointer local
   (`s32* flag = &D_801B60A0;`) instead folds to two independent `lui`/`lw` pairs, because cse knows
   the pointer holds a constant address and rewrites `(mem (plus (reg) K))` back to the symbol. The
   array-element form never gives it that handle. This is the `#base-register-vs-displacement`
   table's own "read it as an array element" row applied to the *base*, and it is the same edit
   `func_80052A68` needed for `D_801B6090` in this sprint.
2. **The preheader placement comes from reading the bound at the TOP of the loop body, not before
   the loop.** `scan_loop` refuses to hoist a MEM when `(maybe_never || call_passed) &&
   may_trap_p (src)` (`loop.c:715`); `may_trap_p` is 1 for any `REG`-based address
   (`rtx_addr_can_trap_p`, `rtlanal.c:136`); and `maybe_never` is set by the first `JUMP_INSN`
   scanned inside the loop (`loop.c:930`), which here is the body's own `if (val0 < val1)` branch.
   So a bound read at the *bottom* — the natural `while (i < D_801B60A0[-2])` test — is scanned
   after that branch and can never be hoisted. The same read written as the first statement of the
   body is scanned before it, `maybe_never` is still 0, and `loop.c` hoists it into the preheader as
   the ROM's single `lw t0,-0x8(s4)`. Spelling it as a pre-loop local
   (`count = D_801B60A0[-2];` before the `do`) is what re-folds the base and costs 3 instructions.

**This generalises**: whenever the ROM hoists a memory read out of a loop whose body branches, the
source has to read it inside the body, above the first branch. A pre-loop local is not the same
thing to gcc — it is a straight-line read that cse can fold — and a bottom-of-loop test is
unhoistable by construction.

What remains is one empty delay slot. reorg fills the guard branch from its fall-through thread,
skipping the non-movable `lw` and taking the `sll` behind it; the ROM's reorg did not. The untested
hypothesis is branch prediction: `fill_eager_delay_slots` fills from whichever thread
`mostly_true_jump` calls likely, and had the ROM's build predicted this forward guard *taken* it
would have filled from the post-loop thread, whose first insn is a `bgez` and therefore unfillable.
Nothing measured supports or refutes that yet — check it with `-dd` before anything else.

## Levers byte-confirmed here (do not re-derive)

1. **Index temps** (`s32 idx0 = arg0 * 184 + i * 2;` then `(&D_801B71FB)[idx0]`) keep `%lo` in the
   load displacement. The inline `(&D_801B71FB)[arg0 * 184 + i * 2]` form makes the address
   `(plus (reg sum) (reg symbol))` and `loop.c` hoists `la t0,D_801B71FB` into the preheader
   (`#base-register-vs-displacement`, the S314 lever, third confirmation in this TU).
2. **Three separate `abs` sequences, two spellings.** The ROM's first two are
   `bgez sN,+3; move vX,s1; negu vX,s1` and come from the ternary `(diff < 0) ? -diff : diff`; the
   third is `move v1,s1; bltzl v1,+2; negu v1,v1` and comes from the explicit-temp
   `mag = diff; if (mag < 0) mag = -mag;`. Writing the second as a ternary lets cse merge it into the
   first — that costs 3 instructions and 2 `nop`s, since the freed `slt` then fills a `bnel` delay
   slot. Giving it its own explicit temp (`span`) restores all three.
3. **`if (diff < 0) return 2; return 1;`**, not `if (diff >= 0) return 1; return 2;`. The ROM's
   `bgez s1,<ret 1>` needs the taken arm to be the `return 1`; the then-arm-return spelling emits
   `bltz` (the memory `else-arm-return-vs-then-arm`).
4. `return (limit == 0) ? 3 : 0;` produces the ROM's `sltiu v0,s0,1; negu; andi 3` const-select.
