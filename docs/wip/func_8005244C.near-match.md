## Attributed

The residual is the S261 `#base-register-vs-displacement` **mutual exclusion**, reproduced on a
second address pair (`D_801B6098` / `D_801B60A0`, 8 bytes apart). The two properties the ROM has
together are each reachable, and each disables the other:

- **`-8(s4)` addressing off a held base** requires the loop-bound read to go through a pointer
  (`s32* flag = &D_801B60A0; ... flag[-2]`). Then the MEM address is `(plus (reg) (-8))`, and
  `rtx_addr_can_trap_p` (`rtlanal.c:136`) returns 1 for a `REG` base, so
  `may_trap_p` is true. `scan_loop`'s movable test (`loop.c:715`,
  `! ((maybe_never || call_passed) && may_trap_p (src))`) then refuses to hoist it — and
  `maybe_never` is 1 here because the loop body's `if (val0 < val1)` branch is a `JUMP_INSN`
  scanned before the bound load (`loop.c:930`). So the load stays **inside the loop**. Measured: 93
  instructions, the only mnemonic delta a single `nop`.
- **Preheader placement** therefore has to come from source (`count = ...` before the loop) or from
  a `SYMBOL_REF` address, which `rtx_addr_can_trap_p` (`rtlanal.c:128`) treats as
  non-trapping so `loop.c` will hoist it. Both spellings make the address a plain symbol, and cse
  then folds the `&D_801B60A0` pointer to direct `lui`/`lw` pairs, so the base is never
  materialized. Measured: 91 instructions (the `sw s4`/`lw s4` pair disappears with the base).
- The 94/94 body takes the third corner: model the region as one object
  (`RoundState* round = (RoundState*)&D_801B6098;`) so the bound is a hoistable symbol address, and
  read the flag through `&round->tie_break_mode`. gcc then anchors its base at the **struct base**
  `D_801B6098` (the loop-resident access wins the base) and folds the flag read, which is the
  mirror image of the ROM's choice.
- Anchoring the other way (`s32* flag = &D_801B60A0; round = (RoundState*)(flag - 2);`) folds
  straight back to 91: cse knows `flag` is a constant address, so `plus(flag,-8)` becomes the
  symbol.

Refuted spellings, all measured, none of which is worth re-running: `count = flag[-2]` in the
preheader (91); `cfg = flag - 3; count = cfg[1]` (91, the banked sibling's idiom — it works there
only because that loop contains `jal`s, so its bound can never be hoisted and the base stays);
`round->hole_count` hoisted to a preheader local (91); `while (i < D_801B6098)` with the plain
symbol (90 — cse merges it with the entry guard's load of the same symbol and the bound load
disappears).

Untried: a form that keeps the `&D_801B60A0` pointer alive with a **third** use, which the ROM does
not appear to have (its `s4` has exactly two uses); and whatever second predecessor of the preheader
block would reset cse's table, the open end S260 left on the sibling case.

## Levers that are byte-confirmed here (do not re-derive)

1. **Index temps** (`s32 idx0 = arg0 * 184 + i * 2;` then `(&D_801B71FB)[idx0]`) keep `%lo` in the
   load displacement. The inline `(&D_801B71FB)[arg0 * 184 + i * 2]` form makes the address
   `(plus (reg sum) (reg symbol))`, and `loop.c` hoists `la t0,D_801B71FB` into the preheader
   (`#base-register-vs-displacement`, the S314 lever, third confirmation in this TU).
2. **Three separate `abs` sequences, two spellings.** The ROM's first two are
   `bgez sN,+3; move vX,s1; negu vX,s1` and come from the ternary `(diff < 0) ? -diff : diff`; the
   third is `move v1,s1; bltzl v1,+2; negu v1,v1` and comes from the explicit-temp
   `mag = diff; if (mag < 0) mag = -mag;`. Writing the second as a ternary lets cse merge it into the
   first (−3 instructions and −2 `nop`s, since the freed `slt` then fills a `bnel` delay slot);
   giving it its own explicit temp (`span`) restores all three.
3. **`if (diff < 0) return 2; return 1;`**, not `if (diff >= 0) return 1; return 2;`. The ROM's
   `bgez s1,<ret 1>` needs the taken arm to be the `return 1`; the then-arm-return spelling emits
   `bltz` (the memory `else-arm-return-vs-then-arm`).
4. `return (limit == 0) ? 3 : 0;` produces the ROM's `sltiu v0,s0,1; negu; andi 3` const-select.
