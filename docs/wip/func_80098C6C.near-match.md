## Root cause (gcc-2.7.2, pass-cited; assembler ruled out)
Binutils rule-out (S282) proved by byte-exact KMC-as reconstruction that ALL nops are as-inserted and
deterministic — 100% of the residual is gcc codegen (see `docs/levers.md` (kmc as noreorder not global nop oracle)).
1. **ORDER (the missing 13th word).** `abs` (adder, ready-delay 2) and the `0.0f` `mtc1` (memory/xfer,
   ready-delay 2) feed the compare with equal `insn_cost`, so the BACKWARD list scheduler has them ready
   the same cycle. sched1: `schedule_select` (sched.c:2615) breaks the tie with `potential_hazard`
   (sched.c:1317) — adder SIMULTANEITY 1 -> blockage 2 (nonzero) beats memory SIMULTANEITY 0 -> blockage
   1 (0); abs wins -> placed LAST (after mtc1). sched2: `priority()` (sched.c:1424) abs=3 vs mtc1=1 ->
   abs first again. Putting `abs.s` BETWEEN the mtc1 and the c.eq.s is what earns the ROM's nop
   (mtc1->cop1 COPROC_MOVE_DELAY, gas tc-mips.c:1312-1339). Costs come from mips.md's
   `define_function_unit`; `ADJUST_COST` (mips.h:2946) only zeroes anti/output deps. Source-invariant
   across 12 spellings (operand swap, hoisted temps, `!(x!=0)`, volatile global, array form, manual
   `x<0?-x:x`, extra block insns, deleted goto). `-fno-schedule-insns -fno-schedule-insns2` reproduces
   the ROM order exactly -> the ROM order is the UNSCHEDULED one.
2. **REGALLOC ($f4/$f2/$f0 distinct vs in-place $f0/$f0/$f2).** local-alloc qty order

## The only crack = empty asm-volatile barriers (PO-DECLINED)
`__asm__ __volatile__("")` emits zero bytes but `sched_analyze` treats it as a full dependency barrier

operand barrier `("" : : "f"(x))` after the `if` holds `x` live -> fixes REGALLOC. With both, 13/13
byte-exact. See `docs/levers.md` (empty asm volatile sched barrier). **PO S282: empty barriers are NOT sanctioned for
banking** (no in-tree precedent; all existing inline asm emits real instructions). Fallback pure C is a
HARD terminal (1 short, no priority tie -> permuter cannot score it).
