## The structural finding: func_8006DFF0 is a GCC nested function of func_8006E210

`func_8006DFF0` takes its argument in `$v0` (`sw $v0,0x10($sp)` + `addu $s0,$v0,$zero`, never
reloaded as an ABI arg) and reads `0x0($s0)` / `0x4($s0)` for the loop counters. The caller side has
`addiu $v0,$sp,0x10` before each of its three `jal`s. That is `STATIC_CHAIN_REGNUM = $v0`
(mips.h:1310) and the chain points at the parent's frame origin, where the parent's `i` (chain+0) and
`j` (chain+4) live. So the child is a nested function *sharing the parent's `i`/`j`*, which is also
why every `i`/`j` access in the parent is a stack load/store rather than a register: both are
address-taken by the child.

Consequence: `func_8006DFF0` is not standalone-bankable and `func_8006E210` cannot be written without
it. They bank as ONE slice (`nested-function-banks-the-parent-too`). It also means the **permuter is
unavailable for this function** - `import.py`'s pycparser aborts on a nested function definition, and
the documented workaround (delete the nested-function parent from a copy) cannot apply when the
parent IS the target.

## Levers that closed 526 of 543 instructions (all reusable)

1. **`s32 off = <full byte offset>;` then `SYM[off]`** - the ONLY spelling that keeps the symbol
   inside the MEM (`lui at; addu at,at,off; lb rt,%lo(SYM)(at)`). Any 3-way sum
   (`SYM[a*2 + i*0xB8]` inline) or a plain 2-way sum in a loop makes gcc materialise the symbol
   address into a pseudo, which loop.c then hoists into the preheader (`la sN,SYM` + `addu`), costing
   4 preheader instructions and losing the per-access `lui`.
2. **Dual off temps around a call** - when the ROM recomputes the same index chain on both sides of a
   `jal` (because the index variable is in memory and the call invalidates it), write
   `off1 = i*K; <call>; off2 = i*K;`. gcc cannot CSE them across the call, so both chains are
   emitted, and each access still gets the single-temp form from lever 1. A single shared temp
   collapses both chains and comes out 5 instructions short.
3. **`goto` loop to defeat loop.c** where the ROM re-materialises everything per iteration; a
   structured loop hoists the symbol addresses. Used for part 1's nested pair.
4. **Read a neighbouring global through the array symbol**: `D_801B6098` is `D_801B6090 + 8`, so
   `D_801B6090[2]` reads it as an ARRAY element. `MEM_IN_STRUCT_P` then makes it may-alias the loop's
   `sh` stores, so loop.c stops hoisting the `(D_801B6098 - 1) * 2` preheader computation the ROM
   recomputes per iteration. This is the `mem-in-struct-index-global-cse` memory applied to a
   *different symbol at a known displacement* rather than to the symbol's own element 0.
5. **Accumulator-form statement split**: `x = SYM[off]; x += call_result;` puts the load's
   destination in the accumulator's register (`lb s0,%lo(SYM)(s0)` + `addu s0,s0,v0`), where
   `x = SYM[off] + call_result` uses a scratch and an extra `move`.
6. **Per-region locals**: giving the `case 2` arm and the team-bet block their own locals instead of
   reusing the function-wide `lo`/`hi` moved `col` from `$s1` to the ROM's `$s0` and removed 40 diff
   lines in one edit. A function-scope local reused across regions builds one long allocno that wins
   a callee-saved register the ROM spends elsewhere.
7. **A CODE_LABEL between an assignment and a conditional branch blocks jump.c's store-flag
   conversion** - see the residual below.
8. **`(u8*)D_801B6090 + 0x2D` as a pointer local** for the child's payout byte, giving the ROM's
   `addiu a3,t1,0x2D` + `lbu 0(a3)`; `(*(RoundState*)D_801B6090).payout` folds to a constant
   `%lo(D_801B60BD)` address instead.
9. **`s32 arr[6]`** (not `[12]`): gcc reserves 0x10 bytes beyond the array here, so the array's
   declared size must be swept against the ROM's frame, not derived from the highest index used.

## The three residual clusters

### R1 - `col = 5` cannot be placed adjacent to its branch (3 instructions)

ROM:
```
    beq  $v1,$v0,end      ; delay: addiu $v0,$zero,-1
    lui  $v1,%hi(D_801B60BE) ; lb $v1,%lo(D_801B60BE)($v1)
    beq  $v1,$v0,.L8006E584  ; delay: addiu $s0,$zero,5
    addiu $s0,$zero,4
```
Any source form with `col = 5;` in the same basic block as the test - `col = 5; if (x != -1) col = 4;`,
`col = 4; if (x == -1) col = 5;`, the if/else, a `switch`, a 2-insn then-block, a copy from another
variable, `alt + 1`, `s8`/`s16`/`u16`-typed `col` - is converted by **jump.c:1139-1250** (the
"x = a; if (...) x = b; and A and B are constants where all the set bits in A are also set in B"
case-3 store-flag conversion, `BRANCH_COST >= 2` on `mips_cpu == PROCESSOR_R4000`) into the
branchless `nor/sltiu/negu/andi 5/ori 4` sequence, +2 instructions. `4 & 5 == 4` makes case 3 apply
in both assignment orders, and `can_reverse_comparison_p` returns 1 unconditionally for `EQ`
(jump.c), so the polarity trick does not help either. The conversion re-fires in every
`! reload_completed` jump pass, so any form gcc can constant-fold before a later pass loses.
The only escape found is `reg_set_last` returning 0 because the backward scan hits a `CODE_LABEL`
(rtlanal.c:867) - which requires `col = 5` to be in an EARLIER basic block. Assigning it in both arms
of the preceding `if (D_801B60BD > 0)` is the best form found: it keeps the ROM's `beq`/`li 4` pair
but puts `li s0,5` in the *first* branch's delay slot (where the ROM has `li v0,-1`) and leaves the
second branch annulled (`bnel`).
**Open question for the re-open: what source form gives `col = 5` in that block without the
conversion?** A permanent label between the assignment and the test would do it, but nothing in the
ROM's control flow jumps there. Consider re-deriving whether the ROM's `s0` is really a plain local.

### R2 - tail copy-loop 2-register permutation (~10 instructions)

The 4x7 scoreboard copy is structurally exact (goto outer loop so the `4` bound stays
re-materialised, `rows`/`grid`/`cols` as explicit locals so the three preheader values are
materialised once, `(s32)`-cast integer-first address arithmetic so the `addu` operand order
matches). The residual is a clean 2-register swap in the two block-local quantities: ROM has
`j -> $v1`, `j*2 -> $a0` (and `i -> $v1`, `4 -> $v0` in the outer block); the build has them
exchanged. Tried and rejected: `s32 jj = j` temp, `++j` in the condition, `cols != j`, byte-offset
casts, pointer temps for the destination, `dst`/`src` declaration order, hoisting `dst`/`src` to
function scope, a goto inner loop, `4 != i`. This is `local-alloc.c qty_compare_1`
(`floor_log2(n_refs) * n_refs * size / (death - birth)`) landing on the other side of a near-tie;
the normal tool is the permuter, which is unavailable (see above).

### R3 - child: `&sub[i]` computed late (~8 instructions)

ROM computes the `sub[i]` lvalue address immediately after loading `i` and `j`, before the `j*2` and
the 184*i chain; the build computes it after, because the `off2` temp (needed by lever 1) is a
statement that precedes the assignment. Inlining the offset restores the order but re-introduces the
symbol hoist (+3). `s32* slot = &sub[i];` before `off2` also restores the order but costs +3 by a
different route. Needs a form that evaluates the lvalue address first AND keeps the offset in a temp.

  **The re-open needs a spelling that changes the emission order of the two address computations, not
  their weight** — the ROM's order is sum, `j`, `j * 2`; the build's is sum, `j * 2`, `j`.
