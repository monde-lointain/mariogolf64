## Fixes already found (folded into the saved near-match)
- **count reload, not cache** — target reloads `g->count` after the `heap3_alloc` call; caching it in
  `n` forces an extra callee-saved reg (s3) and cascades loop2 regalloc. Use `g->count` directly.
- **`D_800C4660 = groupCount`** (NOT `= i`): `= i` extends the counter live range and adds a reg.
- **index order `col + base`** (not `base + col`): matches target `v0 = v1 + t0`.
