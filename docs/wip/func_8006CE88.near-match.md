## What the function does
Clears a u16 grid `D_80106230` (len `D_801B6090`), scans a 0xB8-stride flag-record array
`D_801B71F6` (bumps `arg0` if every record's flag is non-zero), then per-column
(`func_800521C0()..arg0`) walks the `D_801B71FB` flag field, accumulates per-cell counts into
`D_80106230`, writes a 3-byte state block `D_801050BC/BD/BE`, and finally `sprintf`s + prints the grid.

## Cracks that landed (these ARE the faithful structure — keep them)
1. **loop1 reload+`bne`**: the clear must be a POINTER-WALK `*p = 0; p++` (not `arr[i]=0`). An
   `IN_STRUCT`, addr-varying, non-QImode array store is assumed NOT to alias the fixed scalar bound
   `D_801B6090` (gcc-2.7.2 `sched.c:834` `true_dependence` heuristic) → the bound is hoisted/cached
   with `slt`. The pointer deref (`*p`, non-IN_STRUCT, reg address) conflicts → the ROM's per-iter
   `lw v0,0(a0)` reload + `bne`. Loop cond written `i != D_801B6090` gives the `beqz`/`bne` shape.
2. **count-address full materialization** (`lui;addiu` then `lw 0(reg)`, not `%lo`-in-displacement):
   read the bound through a BLOCK-SCOPED pointer `{ s32 *cnt = &D_801B6090; for(...; i != *cnt; ...) }`.
   A single function-scope pointer becomes a 4th callee-saved reg (wrong); block-scoping keeps it a
   per-loop temp (`a0` in loop1) matching the ROM. The loop2 `cnt` must be declared AFTER the
   `func_800521C0()` call so it does not straddle the call (else callee-saved).
3. **byte-offset re-materialize** for the scan/inner flag reads: `s32 off = ...; *(s8*)((u8*)SYM + off)`
   with the array-DECAY cast `(u8*)D_801B71F6` (NOT `&`) + the `off` local — the `func_8006F24C`
   S235 recipe. Produces the ROM's `lui;addu;lb %lo(SYM)(reg)` per iter (no pointer-giv hoist).
4. **`arg0`/`state` s1/s2 (was the big one)**: access `D_801050BC` as an ARRAY `D_801050BC[k]`
   (NOT via an explicit `s8 *state` pointer). The explicit pointer's high loop ref-count out-prioritizes
   the param for `$s1` (`global.c:594-601` allocno priority), forcing `arg0→$s2`. Array-index lets gcc
   auto-hoist `&D_801050BC` into `$s2`/a temp with a LOW direct ref-count → `arg0` wins `$s1`, matching
   the ROM. `D_801050BD`/`D_801050BE` stay separate scalars (init + sprintf use their own reloc; the
   loop uses `D_801050BC[1]`/`[2]` = base+disp, no BD/BE reloc — verified against the `.o` relocs).

## Residual diffs (register allocation only — 3 clusters)
- **Scan `offset`↔`hasZero` (a0↔v1).** ROM: `hasZero=$v1`, `off=$a0`; build: `hasZero=$a0`, `off=$v1`.
  The `off` giv (byte-offset form, required) carries a high loop-weighted `reg_n_refs` → `global.c`
  priority position 4 vs `hasZero`'s position 10, so `off` claims the lower reg `$v1` first
  (`global.c:594-601`, find_reg lowest-free ascending). The ROM colors `hasZero` first (it wins the
  tie by lower allocno number). No source lever raises `hasZero`'s refs or lowers `off`'s without
  changing the emitted byte-offset shape (inline `i*0xB8` → pointer-walk, worse; function-scope `off`
  web-splits, worse).
- **loop1 counter `$a2`(ROM) vs `$a1`(build) + preheader schedule.** ROM materializes `&D_80106230`
  AFTER the guard (fills the branch-delay with the counter init) and colors loop1's `i`-web `$a2`
  (reused later as scan-`n`/`col`); build materializes it before the guard and keeps `i` in `$a1`.
  A local-alloc web-reuse/coalesce choice; separate counter vars are worse.
- **loop2 count double-materialization.** ROM hoists `&D_801B6090` at TWO nesting levels —
  `$t5` (outer-guard read, once) + `$a3` (inner-reload, per outer iter) — then colors the
  `&D_801050BC` loop base `$t0`. The single `cnt` pointer keeps ONE pseudo (`$t0`) for both reads
  (2 insns shorter) and shifts the loop-base to `$a3`, cascading reg renames through loop2. A
  two-pointer split (`cntG` before / `cntR` inside the outer loop) DOES reproduce the two hoists but
  with a messy `t1`/`t5`-copy allocation (net worse, 5520). gcc's two-level loop.c invariant motion
  on a full-address value is not cleanly source-reproducible into the ROM's exact temp assignment.
