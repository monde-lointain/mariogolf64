# func_8004C958 — recursive diamond-square cloud generator (near-match, S263)

**Status:** CARRIED. ~248/274 instr. Structure/semantics fully RE'd. Residual =
register-pressure spill mismatch (`#local-alloc-qty-permutation` class): the ROM
spills more than a faithful-C build does, so mine is ~26 instr SHORTER (mine is
more optimal than the target — a terminal shape).

## What it does
Diamond-square / plasma midpoint-displacement fractal over the current cloud
buffer `D_801B56F0` (`s16[64][64]`, row stride 0x80 bytes, corner-wrap `&0x3F`).
Signature `func_8004C958(s32 level, s32 x, s32 y)`.
- `step = 0x40 >> level`; `half = step >> 1`; `amp = D_800BE6C0[level]` (per-level
  displacement amplitude).
- Read 4 corners: `tl=buf[y][x]`, `tr=buf[y][(x+step)&0x3F]`,
  `bl=buf[(y+step)&0x3F][x]`, `br=buf[(y+step)&0x3F][(x+step)&0x3F]`.
- 5 midpoints, each filled only if currently 0, looping `rand()` until the
  result is non-zero: center `(tl+tr+bl+br)>>2`, top `(tl+tr)>>1`, left
  `(tl+bl)>>1`, right `(tr+br)>>1`, bottom `(bl+br)>>1`, plus
  `((rand()&0xFF)-0x80)*amp`.
- Recurse into the 4 quadrants at `level+1` while `(u16)step > 2`.

## The wall
The ROM stores `step` to `sp+0x1E` (`sh`/`lhu`) and spills 3 corner values
(`tr`→sp+0x26, `br`→sp+0x2E, `bl`→sp+0x36) to the stack, reloading + sign-
extending them in each of the 5 midpoint blocks. This is register pressure from
the 4 recursive-call live ranges (x, y, level, half held in s3/s4/s7/s5). A
faithful-C build keeps step + all 4 corners in registers, so it is ~26 insn
shorter.

Tried and did NOT force the spills: `u16 step` (stayed in a register + got
shorter), inline `(x+step)&0x3F` recompute vs cached `xs`/`ys` (CSE'd back). gcc-
2.7.2 produces tighter code than the ROM here; forcing it to spill from source is
the `mine-is-more-optimal` terminal variant of `#local-alloc-qty-permutation`.
Not permuter-eligible (26-insn count deficit, not a permutation). Re-open only
with a register-pressure lever that makes gcc spill the corners (or a
compile-profile confirmation).
