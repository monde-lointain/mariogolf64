# func_8007399C — near-match (S307, re-measured S308)

## The carve is NOT the blocker any more (S308)

S307 recorded this leaf as `cohort-blocked`: bank it with `func_800754BC` and `func_8007580C` or not
at all. **That is wrong, and the sprint proved it.** The host object's `.rodata` carve splits at any
8-aligned jump-table boundary inside the pool, so S308 moved the carve from `[0xACBE0]` to
`[0xACB38]` and banked the other two leaves (`place_glyph_sprite_run`, `emit_glyph_sprite_dl`) with
`jtbl_800D16D0` still sitting in the extracted `[0xACAD0, rodata]` blob. When this leaf closes, the
carve moves once more, `[0xACB38]` -> `[0xACAD0]`, size `0x110` -> `0x178`. Nothing else is needed:
no sibling, no cohort commit.

## Semantics (re-derived from the `.s`, confirmed by the call site)

Measures the on-screen extents of a stored glyph string. `place_glyph_sprite_run` (`func_800754BC`,
banked S308) calls it as `func_8007399C(runId, size, &w, &h, 0)`.

```c
void func_8007399C(s32 id, s32 size, s32* out_width, s32* out_height, s32 player);
```

- `id` indexes the glyph-run table `D_800E1C48`: `[id*2+2]` is the run's start, `[id*2+3]` its length.
- Each code unit is `D_800E1C48[0][D_80104FD0 + start + i]`. Both globals are re-read every
  iteration, so they must stay direct global references.
- `c < 0x100` is an ordinary glyph: `0xDE`/`0xDF` are skipped, `size == 0xC` adds the per-glyph
  advance `D_800C4390[c]`, anything else adds `size`.
- `c > 0x7FFF` dispatches through `jtbl_800D16D0` on `c - 0x8000`, 26 dense arms: 25 = newline,
  15 = `sprintf` the player-name buffer, 20-23 = a per-player s32 at `D_8013F4DC[c-0x8000]` offset by
  `player * 44`, 0-10 and 12-14 = fixed `0xC`, the rest = no advance.
- The three width slots start from the 12-byte zero template at `D_800D16C0`; the result is
  `max(w[0], w[1], w[2])`, stored to `*out_width` **twice**, and the accumulated height to
  `*out_height`.

## Body — replay this, do not re-derive (149/149, exact frame, 70 lines)

typedef struct {

extern LineWidths D_800D16C0;

## The residual: one cause in block 0 (`sched.c`, pre-reload)

`cmpfn` lines 2-31 are block 0 in a different order, and lines 35-36 / 100-102 follow from it. The
ROM's block 0 is:

```
sw a3,0x24(sp)      # spill out_height
lw a3,0x60(sp)      # player, REUSING a3
... callee saves + the a1/a2 parameter copies ...
lui a2,%hi(D_800D16C0) ... sw a1,0x18(sp)     # the 12-byte template copy
lui v0,%hi(D_800E1C48); lw v0,%lo(...)        # the run-table pointer
move s4,zero        # total = 0
sll a0,a0,2; addu a0,a0,v0; lhu s5,6(a0); lhu s7,4(a0); beqz s5
```

Mine loads `player` first (into `t0`/`a2`/`t1` depending on the spelling) and the run-table pointer
second, and puts the `out_height` parameter copy at the **end** of block 0, so the incoming `$a3` is
live across `player`'s definition and `player` cannot colour `$a3`. Everything else in the diff is
that one colouring plus its knock-on order.

**The pass is `sched.c`'s pre-reload birthing boost, not `rank_for_schedule` priority.**
`adjust_priority` (sched.c:2506) raises an insn to `max_priority` when `birthing_insn_p`
(sched.c:2469) holds: the insn is a `SET` whose `REG` destination is live at that point **and whose
pseudo has `reg_n_sets == 1`**. Both parameter insns qualify, so both are boosted; a boosted insn is
selected as soon as it is ready, and because `schedule_block` runs bottom-up, *selected early means
placed late*. The `out_height` copy has no in-block dependent, so it is ready at T-2 and lands at the
bottom; the template copy (a `PARALLEL` with a `MEM` destination) can never be boosted, so it floats
to the top. Reading the `-dS` dump for block 0 is what shows this:

```
;; ready list at T-2: 19 (7f000001) 22 (1) 54 (3), now 19 54 22
```

`19` is the `out_height` copy at `7f000001` = `LAUNCH_PRIORITY`. **If it were unboosted it would be
selected last and placed first, which is exactly the ROM's layout** — the tie against the template
copy then breaks on LUID, and `assign_parms` gives the parameter copy the smaller LUID.

So the open question is a single one: **what source form gives the `out_height` parameter pseudo a
second `SET`** (`reg_n_sets > 1`), since that is what removes the boost. Every folded spelling
(`out_height = &out_height[0]`, `+ 0`, `| 0`, a self-copy, an aliasing local `s32* oh`) is optimised
away before `sched1` sees it, and a real second assignment changes the instruction count.

## The requirement, stated exactly (S309, from the `-dS` ready lists)

S308 named the pass; this states what a candidate source form has to satisfy, and it is two
conditions, not one. Block 0 holds ten schedulable insns. `schedule_block` walks **bottom-up**, so
*selected first means placed last*, and the selection rule is: highest priority wins, ties break on
**descending LUID** (source order). Boosted insns carry `7f000001`, everything else `1` or `3`.

Mine, and what each insn is (numbers from the baseline body above):

| insn | what | boosted? |
| --- | --- | --- |
| 19 | `oh = out_height`, the `a3` copy | **yes** (`reg_n_sets == 1`) |
| 12 | the 5th-argument (`player`) load | yes |
| 22 | `total = 0` | no (`total` is the loop accumulator, 2 sets) |
| 28 | the `D_800D16C0` template block move | no (`PARALLEL` with a `MEM` dest) |
| 33 | the `D_800E1C48` load | yes |
| 37/39/44/54/57 | `sll`, `addu`, the two `lhu`, `beqz` | 44/54/39 yes |

Selection mine: `57 54 19 44 39 37 28 33 12 22` -> placement `22 12 33 28 37 39 44 19 54 57`.
Selection the ROM needs: `57 54 44 39 37 22 33 28 12 19` -> placement `19 12 28 33 22 37 39 44 54 57`,
which is the ROM's block 0 line for line.

Reading the two orders against each other gives both conditions:

1. **Insn 19 must be unboosted** (`reg_n_sets(oh) >= 2`), so it stops being selected at T-3 and falls
   to T-10, which places it first — and that is what frees `$a3` for `player`.
2. **`total = 0` must have a HIGHER LUID than the template copy**, i.e. the `w = D_800D16C0;`
   statement must come *before* `total = 0;` in the source. Both are priority 1, so at T-6 the tie
   breaks on LUID and the ROM picks `total = 0` there, the template copy at T-8. With the doc's
   statement order the tie goes the other way. This is why S307's 12-permutation sweep read "does not
   touch the colouring": condition 2 is invisible until condition 1 is met.

## Refuted at zero cost (S309, all measured; base = the 70-line body)

| form | result |
| --- | --- |
| `s32* oh = *(&out_height);` (address-taken **parameter**) | 150 instr, 293 lines. An addressable parameter is homed at its incoming slot `0x5C`, not the ROM's local `0x24`, and the store still lands after the register saves |
| `s32* oh; s32** ohp = &oh;` (address-taken **local**) | 149/149, exact frame, **80** lines. The store is no longer a `SET` of a `REG` so the boost is gone, but the slot moves to `0x20` and the store is still placed 17th, because a `MEM`-dest insn with no in-block consumer is ready from T-2 and simply loses every tie |
| drop `oh` entirely, `*out_height = total;` | 149/149, exact frame, 80 lines, and the spill slot is back at the ROM's `0x24`. The copy insn survives as insn 19 regardless — the parameter is live across four calls, so `cse` cannot substitute `$a3` the way it does for `id` in `$a0` |
| `oh` re-set from `out_height` immediately before the final store | 80 lines; `cse` folds the pair and the block-0 copy disappears instead of gaining a second set |
| `oh` re-set at the tail of the `if (count != 0)` body | 152 instr (+3) |
| `oh` re-set inside the `if (max < w.v[2])` arm | 154 instr, frame `-0x58` |
| reuse the `row` pseudo as the out-pointer (`row = (u16*)out_height;` + `*(s32*)row = total`) | 150 instr (+1), 123 lines. It *does* unboost the copy — only one insn now hoists above the saves, as in the ROM — but the reuse costs one `move` and the copy still is not selected last, because its LUID is above `total = 0`'s |

So every spelling that gives the pseudo a real second set costs at least one instruction, and every
spelling that removes the `SET`-of-`REG` shape (addressable local, direct parameter) leaves the insn
ready from T-2 with nothing to lose a tie to. The two known-free directions are both closed:
`sched.c:3196-3213` does skip the leading parameter copies out of the scheduling range entirely, but
that region ends at the first non-`INSN` in the chain, and every body statement sits after
`NOTE_INSN_FUNCTION_BEG`; and the sibling entry copies it *does* skip (`move s1,a1`, `move s8,a2`)
print interleaved with the register saves, not ahead of them, so being skipped would not put the
store where the ROM has it either.

## Next probe

Find a source form that gives `oh` a second `SET` whose insn is deleted by `local-alloc` copy
coalescing rather than by `cse` — the one class not yet tried, since `cse` folding is what killed
three of the seven forms above. `tools/allocno_report.py` on a candidate says whether the second set
coalesces before it says anything about registers. A `gcc -dS` dump of block 0 is a 30-second check:
the fix is confirmed the moment insn `19`'s ready-list entry reads `(1)` instead of `(7f000001)`,
**and** `total = 0` is selected at T-6 rather than T-10.
