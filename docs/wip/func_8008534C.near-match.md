# `func_8008534C` near-match (S304)

`src/main/func_80080220.c`, `0xC4C` / **787 instructions**, 15 `jal`, 70 FP mnemonics, frame
`-0x118`, 241 stores, 9 branches. A `dl-emitter` from the S298 vein.

**State: 787/787 with the ROM's exact `-0x118` frame, an identical mnemonic histogram, and every
instruction from position 100 to the end byte-identical.** The whole residual is 135 `cmpfn` rows in
the first basic block. The body below is the current best; reproduce it before doing anything else.

## What the function is

The club/wind head-up overlay, emitted into one `Gfx**` chain. It resets the projection matrix and
the render state, draws up to two wind arrows (delegating to the already-banked
`emit_wind_indicator_dl`), then composites two independent panels, each guarded by its own pair of
flags: a 32x32 RGBA16 club-face swatch rotated by `D_80106238`, and a two-tile 48x24 power meter
rotated by `D_8010623A`. Both panels build their model matrix with `func_80065A1C` and hand it to
`convert_and_pack_floats_to_fixed`, then draw a quad (`gSPVertex` + `gSP2Triangles`) through
`D_E1F50` / `D_E1FD0`.

Signature: `void func_8008534C(Gfx** gfxp)` -- `$a0` is kept in `$fp`, `lw $v0, 0x0($fp)` loads
`*gfxp`, and `sw $v0, 0x0($fp)` at `.L80085F60` writes the advanced pointer back.

## Method

`venv/bin/python3 tools/dl_decode.py asm/nonmatchings/main/func_80080220/func_8008534C.s` gives the
74-packet stream in list order plus a program-order event list of the branches and calls, which is
what makes the two-panel control flow readable. `tools/rdp_word.py` and the host macro harness
(`gcc -m32 -w -I include -I include/libultra -I include/libultra/PR`, local `_SHIFTL`/`_SHIFTR`,
and **no local `u32`/`s32` typedefs** -- `ultratypes.h` defines them and a duplicate is a hard
error) settled every composite:

| words | macro |
| --- | --- |
| `FC119623 / FF2FFFFF` | `gDPSetCombineMode(G_CC_MODULATEIA_PRIM, G_CC_MODULATEIA_PRIM)` |
| `E200001C / 00553048` | `gDPSetRenderMode(G_RM_AA_TEX_EDGE, G_RM_AA_TEX_EDGE2)` |
| `D9000000 / 0` | `gSPLoadGeometryMode(0)` |

| `D9FFFFFF / 00200404` | the same plus `G_SHADING_SMOOTH` |
| `FD10.. E8.. F5000100 E6.. F0000000/0703C000 E7..` | `gDPLoadTLUT_pal16(0, addr)` (6 packets) |
| `FD10.. F5100000 E6.. F3000000/073FF100 E7.. F5101000 F2000000/0007C07C` | `gDPLoadTextureBlock(addr, RGBA, 16b, 32, 32, ...)` (7 packets) |

`D_800D1B78`/`D_800D1B88` are `pi` and `D_800D1B80`/`D_800D1B90` are `2 * pi`, read straight out of
`baserom.z64` (main segment vram - `0x80024C00` = file offset). They are four **separate** pool
entries for two textually distinct occurrences each, exactly as the S298 one-entry-per-occurrence
rule predicts, so they stay `extern const f64` and this body emits no `.rodata` of its own
(`objdump -s -j .rodata` on the object: no such section).

## Residual, and the four levers that got here

First build: 787/787, frame `-0xC0`, 491 rows. Then, in order:

| lever | result |
| --- | --- |
| first build | 787 / `-0xC0` / 491 rows / `addiu` -1, `lui` +1 |
| `f32 unusedA[4]` + `f32 unusedB[18]` between `pos` and `model`, `RomLoadSlot buf[2]` **block-scoped** to the first panel | 787 / **`-0x118`** / 177 |
| block-scoped `f32* arrow = &D_8022D684;` | 787 / `-0x118` / 151, histogram **exact** |
| one `f32 angle` split into two block-scoped locals | 787 / `-0x118` / **135** |

Two of those are reusable results:

- **An address-taken scalar takes its frame slot at the first `&x`, after every function-scope
  aggregate, so a block-local aggregate declared later lands *above* it.** That is the only way to
  get the ROM's `gfx` at `0xC8` with `buf` at `0xD0`; with `buf` at function scope the order
  inverts. The 88 bytes of dead frame (`0x30-0x3F` and `0x80-0xC7`) are shape-insensitive --
  `s32` vs `f32`, `[18]` vs `[4][4]`+`[2]`, `[3]`+scalar all give the same 135.
- **The `f32* p = &SYM;` pointer lever must be block-scoped.** The ROM materialises
  `&D_8022D684` once (`lui`+`addiu` into `$s2`) and reads `0x0($s2)` on both sides of the
  `emit_wind_indicator_dl` call, while `D_8022D688` next to it keeps its own `%hi` per access; that
  one address CSE *is* the entire `lui` +1 / `addiu` -1 histogram delta. At function scope the same
  pointer costs +1 instruction and 1532 rows. This is the same idiom the banked sibling
  `emit_wind_indicator_dl` uses for `f32* wind = &wind_dir_angle_rad;`.

## What is left

All 135 rows are in instructions 0-99. The ROM emits the ten preamble packets as **twenty
`v0`-based word stores first, then ten `addiu $v1,$v0,K` + `sw $v1,0xC8($sp)` pairs**, and reads
the `D_80106242` branch condition *after* the stores; this build interleaves one pointer update per
packet and hoists the condition load to the top. Neither side is in source order -- the ROM stores
`0x0, 0x4, 0x2C, 0x3C, 0x40` before `0x8`, so both schedules are `sched` output, and the difference
is which insns won the ready-list ties.

Measured and rejected, all at 135 or worse (record the base: the body below):

| form | result |
| --- | --- |
| `Gfx* gfx = *gfxp;` as an initialiser instead of a separate statement | 135 |
| `gfx` declared first / after `pos` / `club` before `gfx` / `club` block-scoped | 135 |
| `unusedA`/`unusedB` retyped or reshaped (4 variants) | 135 |
| a braced block around the whole preamble | 135 |
| `do {} while (0);` after the last preamble packet | 788, 1532 rows |
| first condition inverted into an `if/else` | 788, 1554 rows |
| `gDPPipeSync(gfx); gfx++;` split across the preamble | 788, `sw` +1 |
| the same split across every simple `gfx++` in the body | 767, `addiu` -10, `sw` -10 |
| permuter, `--settings permuter_settings_main.toml`, 370 iterations, 15 threads | base 2550, best 2435; the "best" candidate is an injected `(double)` cast, i.e. noise |

`gDPNoParam` is `{Gfx *_g = (Gfx *)(pkt); _g->words.w0 = ...; _g->words.w1 = 0;}`, so the queued
post-increment flushes at the end of the declaration-with-initialiser and the increment is *always*
emitted before the two word stores; the ROM's grouping therefore has to come from the scheduler, not
from a source spelling of the increment. **Next axis: a `gcc-2.7.2 sched.c` dive on
`rank_for_schedule` (why the dead `0xC8($sp)` stores lose the tie here and win it in the ROM), not
another source sweep.** The mnemonic histogram against the `.s` is the measurement that found the
original class here and is worth running before any other oracle:

```
grep -oE '  [a-z0-9.]+ ' <fn>.s | tr -d ' ' | sed 's/^addu$/move/' | sort | uniq -c
grep -oE $'\t[a-z0-9.]+\t' mine.txt | tr -d $'\t' | sed 's/^li$/addiu/' | sort | uniq -c
```
