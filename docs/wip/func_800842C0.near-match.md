# func_800842C0 — chain-USED GCC nested function (glistp via static chain in $v0)

**Status:** CARRY (blocked on parent). Not a raw-DL-word regalloc wall — the block is the
GCC nested-function calling convention. Crackable once the parent `func_80084468` is
decompiled and this body is written as a nested function inside it.

## What it is

`func_800842C0(col, row, char* str)` is a texture-rectangle glyph-string emitter: it walks a
NUL-terminated string in `a2`, classifies each char (space `0x20` skip, `'m'`=0x6D special
glyph index 0xE/0x77, digits `'0'`..`'9'` -> `(c-0x30)` -> atlas index `*12`), and emits a
`G_TEXRECT` (0xE4000000) + `G_RDPHALF_1` (0xE1000000) + `G_RDPHALF_2` (0xF1000000) +
`0x04000400` display-list block per glyph, advancing the glist pointer by 8 bytes per command.
The col/row coords are clamped with the `((x<<18)>>16` sign / `nor;sra 31` mask +`& 0xFFC`
scissor idiom (kin to the func_80071370.c raw-DL-word glyph family).

## Why it is a nested function (the $v0 tell)

The glist pointer is NOT a parameter and NOT a fixed global — it is a LOCAL of the caller,
reached through the GCC static chain (`STATIC_CHAIN_REGNUM = $v0`, mips.h:1310):

- child prologue: `addu t7,a0,zero` (col), `sw v0,0(sp)` (spill the chain), `addu t0,v0,zero`
  (t0 = chain). Then per glyph: `lw a1,0(t0)` = `*(chain+0)` = parent's glistp;
  `addiu v0,a1,8; sw v0,0(t0)` advances it in place; DL words store to `0(a1)`/`4(a1)`.
- v0 is READ before any def -> incoming value in $v0, i.e. the static chain, not an ABI arg.

## Parent confirmation (func_80084468, [0x5F868], 0xA54)

- `asm/.../func_80084468.s:582` `addiu $v0, $sp, 0x10` sets the chain = &(local at sp+0x10)
  right before the emit loop.
- The parent keeps its glistp at `0x10($sp)` (many `sw $v0, 0x10($sp)` maintaining it) and
  RELOADS it after each child call (`lw $v0, 0x10($sp)` immediately after `jal func_800842C0`
  at `:611`), exactly the chain-local round-trip.
- The parent genuinely `jal`s the child (out-of-line, real xref at 0x80084DB4) — NOT inlined —
  so this is a live nested function, not an orphaned inlined body.

## Unblock path

Write `func_800842C0` as a nested function inside the decompiled `func_80084468` TU: declare a
local `Gfx* glistp` (homed at sp+0x10 in the parent) and a nested
`void emit(s32 col, s32 row, char* str){ ... *glistp ... }` that closes over it; GCC-2.7.2 then
homes the chain in $v0 and the child reads glistp through it, reproducing both bodies. This is
the [[nested-function-static-chain-spill]] "chain-USED" case (mirror of the S248
`func_80092E10` re-price). Parent is a ~2644B FP-heavy DL builder — its own slice.

Standalone `volatile`/uninitialized byte-repro does NOT apply here (that is only for the
ORPHANED-inlined variant with zero ROM `jal`/fn-ptr xrefs; this child has a real caller `jal`).

See `docs/hazards.md#nested-function-static-chain-spill`.
