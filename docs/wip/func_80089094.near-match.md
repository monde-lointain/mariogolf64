## F3DEX2 reconstruction and exercised evidence

The repository's `dl_decode.py`, `rdp_word.py`, and `gbi_match.py` supplied the needed packet
order, fields, render-mode pairs, and combiner names; additional tool vendoring was unnecessary.
The candidate reconstructs the initial render states, icon render states, shared HUD states,
shot-panel states, final debug texture block, and the complete player-icon loop using SDK macros.
Remaining raw display writes use `Gfx.words` fields rather than untyped word dereferences.

Two throwaway 32-bit host harnesses compiled against the repository's own `gbi.h` with
`-DF3DEX_GBI_2 -D_LANGUAGE_C` and executed successfully:

1. The SDK player-icon loop equaled the prior ROM-derived packet-store reconstruction for
   **100 cases / 8000 command words**: x values `-60`, `-4`, `0`, `246`; active player `-1..3`;
   player counts `0..4`. Both packet words and cursor advances were compared. Each icon emits
   20 packets; negative-x clipping and active/inactive scaling both passed.
2. Six converted state/texture blocks equaled **72 packets / 144 ROM-derived words**, including
   the initial dither states and final 32x32 RGBA16 debug texture. This check caught an incorrect
   environment-color spelling: ROM command `0xF9000000` requires `gDPSetBlendColor`, not
   `gDPSetEnvColor` (`0xFB000000`). The corrected source passed the complete comparison.

These checks cover the converted packet regions, not the entire renderer or emulated gameplay.
Temporary harnesses were removed automatically. Compiler/binutils source inspection is deferred
until the remaining structural deficits are resolved; scheduling flags were not changed.
