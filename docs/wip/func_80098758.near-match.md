# func_80098758 — near-match carry (S285)

`src/main/func_80095A10.c`, 0x26C / 155 instructions. Best build 158, frame exact.
Body preserved at `docs/wip/func_80098758.base.c`.

## What it does

Scores how flat the terrain is around a candidate position and keeps that position when it beats the
best seen so far. Fully reverse-engineered; the semantics are not in doubt.

1. Samples the terrain height at the centre via `get_interpolated_terrain_height_wrapper(pos[0], pos[2])`.
2. Over four rings (`ring` 1..4) of sixteen samples (`step` 0..15), samples the height at
   `pos + (cos, sin)(step * PI/8) * ring * 15360` and accumulates
   `abs(height - centre) / (ring + 1)`. The FP constants are `0x3EC90FDB` = PI/8 and
   `0x46700000` = 15360.0f.
3. Doubles the score, then, only when `D_800E4CC8 == 0`, walks 128 scenery collision cylinders at
   0x10 stride from `collision_cylinders`, reading x at +0x0, z at +0x4 and radius at +0xC. When
   `calculate_hypotenuse_safe(dx, dz) - (radius << 10) <= 0x12BFF` for any cylinder, the score is
   forced to `0x465000` so the position loses.
4. Stores the position into `D_800E4C98` / `D_800E4C9C` / `D_800E4CA0`, the score into `D_800E4CA4`,
   and sets `D_800E4CC8 = 1` — either unconditionally on the first call, or when
   `score * 2 < D_800E4CA4 && 0xB400 < D_800E4CA4`.

## Residual

A register-allocation permutation, not a structural deficit.

- Frame is exact at `-0x58`, and the FP register set matches (five callee-saved, `fs0`-`fs4`).
- The inner sampling loop is instruction-identical to the ROM, including the `bltzl`+`negu` abs, the
  `div`/`break 7`/`break 6` divide guards, and the `bnel` outer back-edge with `step = 0` annulled in
  its delay slot.
- The count delta is 158 vs 155, and 2 of the 3 are the `sw`/`lw` pair for a seventh callee-saved
  register: my build uses `s0`-`s6`, the ROM uses `s0`-`s5`.

The ROM economises by reusing two registers across the two phases, since the ring-loop values are dead
once the cylinder loop starts:

| ROM register | phase 1 | phase 2 |
| --- | --- | --- |
| `s5` | centre height | the `0x12BFF` threshold |
| `s2` | ring divisor | the blocked flag |
| `s1` | ring | cylinder index |
| `s0` | step | walking cylinder pointer |

## Levers tried, and what they did

- **Splitting the two call arguments into `offset_x` / `offset_z` temps: worked, −1 instruction.**
  Writing both arguments as one call expression makes gcc evaluate and `trunc.w.s` the first argument
  before the `sinf` call and park it in an integer register. The ROM computes both float offsets,
  then loads and adds the position after both trig calls. This is the single most valuable finding
  here and generalises: for a two-argument call whose arguments each cross a call, compute both into
  temps first.
- **Reusing the dead `centre_height` variable for the threshold: no effect on the count.** gcc does
  reuse one register for both roles, but allocates it `s6` rather than collapsing to six.
- **Reusing the dead `divisor` variable for the blocked flag: no effect.** gcc kept a separate
  pseudo, so the source-level reuse did not force the coalesce.
- **`(height <= -1)` versus `(height < 0)` for the abs: no effect** on either count or allocation.

## Verdict

Carried, not terminal. This is a first-attempt wall on the classical `local-alloc` layer, which is
exactly the class the `--loose-stubs main` plateau advisory predicts will read `fresh` until
attempted. It was never taken to exact instruction count, so no pressure or live-length argument
should be quoted from this measurement.

Next attempt should reach 155 first. The remaining +1 beyond the register pair is unaccounted for and
should be identified before any coloring lever is tried. A compiler-source fan-out is the documented
escalation for a register-allocation carry, and per `docs/workflow/fan-out.md` this shape — a
scattered permutation rather than a single-operand residual — is a fan-out target, not a permuter
target.
