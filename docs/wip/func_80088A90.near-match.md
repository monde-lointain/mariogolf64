# func_80088A90 near-match (S254 carry, re-cracked S258)

Main-segment glyph/units-string display-list emitter in `src/main/func_80080220.c`
(0x14C / 332B / 83 instrs). Renders a numeric measurement string as one
`gSPTextureRectangle` per glyph.

| sprint | build instrs | asm-differ score | verdict |
| ------ | ------------ | ---------------- | ------- |
| S254   | (raw-DL-word reconstruction) | — | "terminal: regalloc + reorg branch-likely, not source-leverable" |
| S258   | **83 (exact)** | 913 | one extra callee-saved register (local-alloc); everything else reproduced |

**The S254 terminal verdict was wrong.** Both claimed-unreachable features are
reachable from faithful C:

- the redundant `andi v1,t0,0xFF` (raw char in `t0` for the loop test, masked
  copy in `v1` for the compares) comes from splitting the char into a `u8`
  variable for the `!= 0` loop test and a separate `s32` for the classification
  (`ch = c;` inside the loop) — the QImode->SImode extend then lands in a
  DIFFERENT basic block from the `lbu`, so combine cannot fold it away, and the
  `s32` keeps the range test signed (`slti`, not the `sltiu` a plain `u8 ch`
  gives);
- the `beql v1,s0,.L…; addiu a3,a3,1` branch-likely on the space case comes from
  making the space handler an OUT-OF-LINE block (`goto skip_char;` with
  `skip_char:` placed down with the glyph handlers). As an inline `if` body gcc
  lays it out fall-through and emits `bne`+`nop`+`j`+`addiu`; once the block is
  out of line and one insn long, reorg's `optimize_skip` folds it into the
  annulled slot and deletes the block.

## Best reconstruction (S258, 83 instrs = exact, emit block byte-identical)

```c
void func_80088A90(Gfx** holder, s32 x, s32 row, u8* str) {
  Gfx* dl = *holder;
  u8 c;
  s32 ch;
  s32 glyph;
  s32 width;
  s32 new_x;

  c = *str;
  if (c == 0) {
    goto end;
  }

  do {
    ch = c;
    if (ch == 'f') {
      goto glyph_f;
    }
    if (ch < 'g') {
      if (ch == ' ') {
        goto skip_char;
      }
      width = 4;
      if (ch == '.') {
        goto glyph_dot;
      }
      goto digit;
    }
    width = 8;
    if (ch == 'm') {
      goto glyph_m;
    }
    if (ch == 'y') {
      goto glyph_y;
    }
    goto digit;

  skip_char:
    str++;
    goto next;
  glyph_dot:
    glyph = 0x70;
    goto emit;
  glyph_m:
    glyph = 0x50;
    goto emit;
  glyph_y:
    glyph = 0x58;
    goto emit;
  glyph_f:
    width = 0x10;
    glyph = 0x60;
    goto emit;
  digit:
    width = 8;
    glyph = (*str - 0x30) << 3;

  emit:
    new_x = x + width;
    gSPTextureRectangle(dl++, x << 2, row << 2, new_x << 2, (row + 0xC) << 2,
                        G_TX_RENDERTILE, glyph << 5, 0, 1 << 10, 1 << 10);
    x = new_x;
    str++;
  next:
    c = *str;
  } while (c != 0);

end:
  *holder = dl;
}
```

Signature is `(Gfx** holder, s32 x, s32 row, u8* str)`; the caller
(`func_80089094`, 5 call sites) passes the address of its glist pointer.

## What the macro rewrite bought

The S254 attempt wrote the per-glyph block as six raw `u32` stores through a
hand-managed `p += 2` cursor. Writing it as ONE `gSPTextureRectangle(dl++, …)`
makes the emit block come out byte-identical, including:

- the `-4(a2)` / `0(a2)` store pair with `addiu a2,a2,8` between pairs (gcc
  picks `&g->words.w1` as the base and reaches `w0` at `-4`);
- the loop-invariant hoist of `word_hi = (((row+0xC)<<2)&0xFFF)|0xE4000000` and
  `word_lo = (row<<2)&0xFFF` plus the three constant command words into the
  preheader — the same loop.c invariant hoist that puts the five character
  literals (`'f' ' ' '.' 'm' 'y'`) into registers, which is the ONLY reason this
  leaf has a stack frame at all (it must save the s-regs holding them);
- `sll v0,t0,21` for the `s` argument, from `glyph << 5` feeding the macro's
  `_SHIFTL(s,16,16)`.

The glyph map is `'f'`->s 0x60 width 0x10; `'.'`->0x70 w4; `'m'`->0x50 w8;
`'y'`->0x58 w8; digit->`(*str-0x30)<<3` w8; `' '`-> advance `str` only. The rect
is `x..new_x` by `row..row+0xC` in quarter-pixel units, tile 0, s/t = glyph<<5
and 0, dsdx = dtdy = 1<<10.

## Residual (S258)

One extra callee-saved register. The ROM holds the five hoisted char constants
in `s1,s0,t9,t8,t7` (2 saved regs, frame 8) and REUSES the dead raw-char reg
`t0` for the glyph value in the handler stubs; my build holds them in
`s2,s1,s0,t9,t8` (3 saved regs) because local-alloc gives the glyph its own
`t1`, so `t7` goes to a constant. That single decision renames most of the
loop's registers, which is why the score is 913 despite the identical
instruction count and the identical emit block.

The count still lands exactly on 83 because the extra `sw s2`/`lw s2` pair is
offset by two delay slots my build fills from the branch TARGET
(`li t0,<glyph>` pulled out of a handler stub) where the ROM fills them from
BEFORE the branch (`li v1,<width>`). The two effects are coupled: variants that
fix the delay-slot fill (assigning `width` inside each handler instead of before
the test) lose the `beq`-toward layout and come out at 81 instrs.

Not re-attempted with the permuter this sprint (the `func_80087CB0` permuter had
the machine). This is now a local-alloc quantity-ordering residual
(`#local-alloc-qty-permutation`), NOT the S254 "reorg branch-likely +
char-mask-split, unreachable from C" verdict.
