Best build: **296/294**, frame `-0x30` matches, bodies and register roles otherwise aligned.
The attempted C is saved verbatim as `nonmatchings/func_8005CA48/attempt.diff` (a diff against the

## What the function does (fully re-derived from the `.s`, not from a decompile)

Resets the four active-player slots and repopulates them from either the saved profiles or the
flag-0x54 fallback template.

| symbol | shape | role |
| --- | --- | --- |
| `D_800FE3D8` | stride 0x16, 4 entries | active-player slot: `s16` at +0/+2/+4/+6, 12-byte name at +8 |
| `D_800C2AA8` | `u8[4][12]` | parallel copy of the four slot names |
| `D_800FF1E8` | stride 140 (0x8C) | saved profiles; `+0 == 1` means in use, name at `+1`, character id at `+0x19` |
| `D_800C2B40/48/50/58` | `u16[4]` each | flag-0x54 fallback field values |
| `D_800C2B60` | `u8[4][12]` | flag-0x54 fallback names |
| `D_800C2B92`, `D_800C2B96` | `s16`, stride 8 | roster-grid column / row for each slot |
| `D_800C28E4` | `s16[3][7]` | the character-select roster grid `build_roster_grid` fills |
| `D_800BB264` | stride 0x2D8 | per-character record, indexed `slot + 14`; fields at +0, +6, +0x1A |

Body: zero the four slot records and their names; zero the parallel name array; tally
`D_800FF1E8[n*140] == 1`; `flag_is_set(0x54)` forces the tally to 4; clamp to `(0, 4]`; then per slot
copy 12 name bytes into both name arrays, write `slot + 14` into
`D_800C28E4[D_800C2B96[slot]][D_800C2B92[slot]]`, and fill the slot's four `s16` fields either from
the fallback tables (flag set, also writing three of them back into the character record) or from the
character record itself (flag clear).

## Levers that were needed and worked

1. **One counter for every inner loop and for the tally.** The ROM holds exactly two `s16`s in
   `$s2`/`$s3` across the first three loops: `$s3` is the inner counter in loops 1 and 2 and then the
   tally accumulator. Separate locals cost two callee-saved registers and read frame `-0x38`.
2. **Zero the inner counter at the head of the outer body, ahead of the field stores.** That makes the
   reset the first instruction of the loop-top block, which `reorg` then steals into the outer
   back-edge delay slot -- exactly the ROM's `bne ...; move $s3,$zero`. Zeroing it in the inner `for`
   header instead leaves the block starting with the row-offset shift, which `reorg` duplicates into
   the delay slot and peels, costing one instruction per loop.
3. **`off` and `record` computed inside each arm of the second `flag_is_set`, not before it.**
   Hoisting them above the call keeps two more values live across it and reads as a whole-arm
   register permutation.
4. **One reused temp for the three record-field loads in the `else` arm.** Separate temps let the
   scheduler clump all three `lhu`s ahead of the stores; the anti-dependency on a single `s16 field`
   restores the ROM's load/store interleave.

## Residual: +2, both in the loop preheader and the tally loop

Measured by segment against the ROM (instruction counts between the same anchors):

| segment | ROM | mine |
| --- | --- | --- |
| prologue + loop 1 | 50 | 50 |
| loop 2 | 27 | 27 |
| tally loop | 21 | **22** |
| `flag_is_set` + clamp + preheader | 17 | **19** |
| main loop body | 179 | 178 |

1. **Tally loop, +1.** The ROM addresses the profile array per access
   (`lui $v0,%hi(D_800FF1E8); addu $v0,$v0,$v1; lbu $v0,%lo(D_800FF1E8)($v0)`); every spelling tried
   makes `loop.c` hoist the symbol into a register instead (`lui`+`addiu` in the preheader, then
   `addu`+`lbu`), which is one instruction longer. Tried and rejected: plain subscript on
   `extern u8 D_800FF1E8[]`, `*(u8*)((u8*)D_800FF1E8 + slot * 140)` with the array declared `s32[]`,
   and pre-computing the byte offset into a local.
2. **Clamp + preheader, +2.** The ROM re-derives the loop bound every iteration
   (`sll $v0,$s3,16; sra $v0,$v0,16` at the bottom, and only `sll $v0,$s3,16` for the loop-entry
   `beqz`), so `$s3` holds the raw `s16`. My build hoists the sign-extension into the preheader
   instead, which adds an `sra` to the entry guard and a `move` to capture it. The loop bottom is
   correspondingly 2 shorter, so this is a placement difference, not extra work.

   The two are coupled through `loop.c`: with the bound hoisted, the two symbols that get the
   remaining callee-saved registers are `D_800C28E4` and `D_800FF201`, where the ROM gives them to
   `D_800C2AA8` and `D_800FE3E0` and re-materializes the other three inline.

## Tried and rejected

- `while (i != 12)` inner loops with the reset at the end of the outer body: 304 (adds an entry guard
  per inner loop, since the counter's value is only zero via the loop-carried reset).
- Explicit `u8* name_base` / `u8* slot_base` locals hoisted before the main loop: 300, frame `-0x38`.
- `goto`-loop for the main loop: 289, frame `-0x28` -- it defeats every `loop.c` pass including the
  two symbol hoists the ROM *does* have, so it is the wrong shape here (contrast
  `docs/levers.md` goto-loop-defeats-loop-strength-reduction, which assumes the ROM has no hoists).
- Early-`return` clamp instead of the nested `if (i > 0) { ... }`: 296, identical output.
- Declaring `i` before `slot` to walk the allocno birth order: 296, identical output.
- Explicit `if (i != 0) { slot = 0; do { ... } while (slot != i); }`: 296, identical output.
