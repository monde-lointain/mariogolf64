# func_800402F4 near-match — code byte-exact, rodata-adjacency blocked

`s32 func_800402F4(s32 color)` (0x800402F4, 0x8C) in `src/main/get_tile_attribute.c`
(`main/get_tile_attribute` bank). Indexes `find_closest_palette_index` through an
11-entry switch jump table.

## Status (2026-10-16)

- **The body is byte-identical to the ROM.** Isolated `/tmp` object diff of the
  compiled body against `build/us/obj/asm/main/get_tile_attribute.o` shows the same
  35 instructions in the same order, and both jump tables byte-for-byte
  (addends `0x1b8..0x1f8` for `ci8_to_rgba5551`, `0x2b0..0x2c8` for this
  function, matching the ROM's `0x80040258..` / `0x80040350..` tables).
- **The ROM still mismatches**, and the mismatch is *layout*, not code.

Body (bankable as-is):

```c
s32 func_800402F4(s32 color) {
  s32 index = find_closest_palette_index(color);
  switch (index) {
    case 1: return 6;
    case 2: return 2;
    case 3: return 1;
    case 4: return 3;
    case 6: return 4;
    case 0:
    case 7: return 0;
    case 8: return 8;
    case 9: return 9;
    case 10: return 5;
    default: return 7;
  }
}
```

## The blocker — measured

With the body inlined and `[0xA5D58, .rodata, main/get_tile_attribute]` carved, the
translation unit's single `.rodata` is **0x58 bytes** (KMC `as` pads the section to
its 8-byte alignment: 0x28 `jtbl_800CA930` + 0x2C `jtbl_800CA958` = 0x54, plus 4
pad bytes). The ROM's C-owned prefix is only **0x54** bytes: `0xA5D84` starts the
asm-owned string `D_800CA984 = "ratio %f,%x"` (12 bytes), then `jtbl_800CA990` at
`0xA5D90`.

Consequences, all observed:

| symptom | measured |
| --- | --- |
| `build/us/mariogolf64.map` | `.rodata 0x800ca930 0x58 obj/src/main/get_tile_attribute.o`, next input section bumped to `0x800ca988` (`+4`) |
| downstream alignment | `A5FD0.rodata.o` lands at `0x800cabd4`, 16-aligned to `0x800cabe0` (`+0x10` total) |
| whole-image shift | entry stub `addiu sp,sp,%lo(nuContNum)` differs (`0x8010c2d0` ROM vs `0x8010c2e0` build) — first differing byte at ROM 0x1038 |
| ROM hash | `de1305ef74eac88fff92476f62f6a338822a0427` in every configuration that inlines this function |
| identical-hash control | building the *same* tree with only this function reverted to `INCLUDE_ASM` restores `e2c4e7a9...` |

This is the mirror of the documented
[`decomposed-one-tu rodata alignment split`](../../hazards.md#decomposed-one-tu-rodata-alignment-split)
case: there the split piece's tail rodata abuts a higher-aligned next-TU constant;
here a C-owned *prefix* whose section tail is alignment-padded overlaps the next
asm-owned constant.

## Fixes tried

1. **Extend the carve over the string** (`[0xA5D58, .rodata, C]` … raw blob moved
   to `[0xA5D90, rodata]`). splat then *does* migrate `D_800CA984` into the
   referencing stub (`build/us/work/asm/nonmatchings/main/get_tile_attribute/get_ground_attribute.s`
   gains a `.section .rodata` block), which makes the C `.rodata` 0x60 and the
   layout exact — **but** splat simultaneously emits the still-asm `get_ground_attribute`
   case labels as *local* `.L…:` labels instead of `jlabel` (global), so
   `A5D90.rodata.o`'s `.word .L80040654 …` cannot link (`undefined reference to
   .L800406xx`, 15 labels). `nm` on the C object confirms the labels are gone from
   the symbol table.
2. **Carve the whole translation-unit rodata** (`[0xA5D58, .rodata, C]` extended to
   `0xA5FD0`, no raw blob). splat migrates only part of the 33 data symbols; the
   link then fails on the rest (`jtbl_800CA9D0`, `D_800CAA7C`, `D_800CAA84`, …)
   plus `Unable to determine a segment for user-declared symbols`.
3. **Define the string as a C literal in the host TU** (`const char D_800CA984[] =
   "ratio %f,%x";`, positioned so gcc emits it third in `.rodata`). This *does*
   produce the exact 0x60-byte section (verified in `gcc -S`: the two `.align 3`
   jump-table blocks followed by the literal), but splat also emits the same
   symbol from the carved stub, so the assembler aborts with
   `Symbol D_800CA984 already defined`.

## Next levers

- Own the whole `.rodata` extent (all 33 symbols) in one object: bank the remaining
  host functions (`get_ground_attribute`, `get_dominant_terrain_attribute`,
  `blend_terrain_color`, `func_80042318`, …) so their literals become real C and no
  raw blob remains in `0xA5D58..0xA5FD0`; the section then self-aligns the way the
  ROM's does (documented fix for the sibling hazard).
- Or teach the extraction step to keep `jlabel` (global) for labels referenced by a
  raw rodata blob that the carve pushed out of the function stub; the two splat
  behaviours (migrate rodata into the stub / emit local case labels) are currently
  coupled.
