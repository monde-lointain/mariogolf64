## Factor 1 (SOLVED): base register s0 vs a0
`&D_800FF4D0` is used as a shared base (`0xC(s0)`=D_800FF4DC load, `0x18(s0)`=D_800FF4E8 store). It does
NOT cross the get_shot_data call, so naive C placed it in caller-saved a0 (no save). **Fix: declare
`base` BEFORE the call so its live range crosses the jal -> GCC allocates callee-saved s0** (saved in the
jal delay slot, frame + all downstream regs then match). D_800FF4D0 stays a scalar extern (other file
funcs use the D_800FF4xx region as separate scalars, so it can't become an array); the `s32* base` local
recreates the shared base without touching them.

## Factor 2 (TERMINAL): cross-jump-tail-merge blocks the annulled bnezl
ROM: `bnezl v0,EXIT` (annulled) with delay `sw zero,0x18(s0)` for the field!=0 store, and a SEPARATE
`sw zero,0x18(s0)` at the v1<=0 tail. The field!=0 store is annulled into the branch (reorg optimize_skip,
reorg.c:1112-1215).
Build: the two identical `base[6]=0` tails (field!=0 arm + v1<=0 arm) get CROSS-JUMP-TAIL-MERGED by
jump.c into one block reached by both branches (plain `bnez`), so optimize_skip never fires (the store is
a jump target, not a fall-through single insn). jump.c runs BEFORE reorg, so the merge pre-empts the
annul. ROM's compile did not merge them (the annul consumed one store first).
