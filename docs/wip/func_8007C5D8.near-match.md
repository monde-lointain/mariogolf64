# func_8007C5D8 — byte-exact body, blocked by the TU's shared literal pool

Sprint S300. Host `src/main/func_80078910.c`, stub at line ~342. 0x938 = 590 instructions,
1 `jal`, 25 FP mnemonics (fp-coord), 8 branch-likely.

## Status

**The C body is byte-exact.** `tools/cmpfn.sh func_8007C5D8 nonmatchings/func_8007C5D8/current.o`
reports `rom=590 mine=590`, `frame rom=-0x68 mine=-0x68`, and every residual line is an
external-target or relocation normalisation (25 relocation slots, each confirmed against
`objdump -r`). The body is preserved at `nonmatchings/func_8007C5D8/base.c`.

It is **not banked**: it cannot be, in a partial bank of this file.

## Why it is blocked

The body's `else if (p->unk_3A == 8)` arm contains a 7-word lookup table that the ROM copies to the
stack from `D_800D1A40` (`.s` lines: `lui a1,%hi(D_800D1A40)` then three `lw`/`sw` batches of 3 plus
one, `0x0`-`0x18` into `0x28(sp)`-`0x40(sp)`). That is gcc's block move of a local array
initializer, so `s32 tbl[7] = {2, 1, 0, 0, 1, 1, 2};` is the correct and only source form — and it
makes the object emit its own 0x20 `.rodata` template.

The ROM places that template at **0xACE40** (`D_800D1A40`, in the generic asm blob
`asm/data/ACD60.rodata.s`). The host object's `.rodata` is carved at **0xACD10** and is currently
0x50 bytes (`mariogolf64.yaml:447`, `[0xACD10, .rodata, main/func_80078910]`). One object's
`.rodata` is contiguous, so adding the template makes it 0x70 at 0xACD10-0xACD80, overlapping the
generic 0xACD60 blob. The 0xE0 bytes between (0xACD60-0xACE40) are FP doubles plus
`jtbl_800D1990`, all owned by still-asm siblings of this TU, so the intervening region cannot be
pulled into the carve either.

This is the same blocker already documented in this file for `func_80079EBC` (S279, comment above
its stub at `src/main/func_80078910.c:310`): a byte-exact body whose constants live in a pool
shared with still-asm siblings. It banks once the pool-owning siblings are also C.

Two escapes were measured and both fail:

- **Reference the template `extern`** (`extern s32 D_800D1A40[]; off = D_800D1A40[idx] << 11;`):
  no `.rodata` emitted, but the stack copy disappears — `rom=590 mine=575`, frame `-0x48` vs the
  ROM's `-0x68`. The ROM genuinely copies to the stack.
- **Reproduce the copy by hand** (`s32 tbl[8];` plus eight element assignments from the extern):
  frame is exact at `-0x68` and no `.rodata` is emitted, but `rom=590 mine=598` — element-wise
  assignment does not reduce to gcc's 3-3-1 batched block move.

A text split that would give the function its own TU (and its own `.rodata` carve at 0xACE40) needs
a subseg boundary at ROM offset 0x579D8, which is 8-aligned, not 16-aligned, so the split is
mechanically blocked.

## Measured, not inferred (S300)

The blocker was confirmed by building it, not by reasoning about the layout. In two steps:

1. The prototype and struct changes below, applied with the stub still `INCLUDE_ASM`:
   `tools/verify-rom.sh` exit 0, ROM SHA-1 green. So those two edits are free — they are not what
   breaks the build, and the banked sibling `func_8007CF10` is unaffected by them.
2. The body inlined on top of that: `make` fails the SHA-1 gate, and `cmp -l` against `baserom.z64`
   reports **22,110,362 differing bytes** starting at 0x1008 — a whole-ROM shift, which is the
   signature of a `.rodata` size change moving every following data symbol, not a codegen error in
   the function.

Both edits were reverted; the tree is green at the S300 bank commit.

## Form

All-SDK-macro: `gDPLoadTextureBlock` / `gDPLoadTextureBlock_4b` for the five texture arms,
`gDPSetPrimColor`, `gDPSetPrimDepth`, `gSPScisTextureRectangle` for the two rectangle arms,
`gDPPipeSync` between. Levers that were needed, in order:

1. `project_point_to_screen`'s third argument is `f32` (raw `lw`), and `a && b` over an FP compare
   materialises a boolean — nest the `if`s instead.
2. fold-associate: the texture address must be spelled `((u32)BASE + K) + off`, not
   `BASE + (off + K)` (`fold-const.c:3722`).
3. `off = p->unk_3B << 12;` must be computed **above** the three leading DL commands: the DL stores
   kill the cached `lb`, forcing the 0x14 arm to re-read `p->unk_3B`.
4. `if (p->unk_28 == 0.0f) goto end;` rather than `if (p->unk_28 != 0.0f) { ... }`. The `!=` form
   emits `sne_sf`/`CC_REV_FP`, so the branch condition is `EQ` and `mostly_true_jump`
   (`reorg.c:1400`, case `EQ` -> 0) fills from the fall-through and loses the annulled `sw`. The
   `==` form emits `seq_sf`/`CC_FP`, condition `NE`, return 1, target thread, giving `bc1tl` plus
   the annulled `sw`.
5. The final `s4`<->`s5` allocno swap: replacing the single `end: *pgfx = gfx;` join plus `goto`s
   with an explicit `*pgfx = gfx; return;` at each of the four early exits raises `pgfx`'s
   `ALLOCNO_N_REFS` from 2 to 5, so `global.c`'s `allocno_compare` orders `pgfx` ahead of `color`
   and `pgfx` takes `s4` as in the ROM. (`jump.c` cross-jumps the four tails back into one.)
