## Residual = pure a0<->a1 allocno swap
- ROM: `pos`->a0 (`move a0,a1` up front), const `0x2E`->a1, `base` extracted directly `sra t0,a1`.
- Mine: `pos`->a1 (incoming reg kept), const->a0, `base` via in-place sll/sra + `move t0,a1`.
Every diff row flows from this single swap; instruction multiset otherwise identical, 40==40.

## Root cause (gcc-2.7.2)
- `global.c:587 allocno_compare` priority = `floor_log2(n_refs)*n_refs / live_length`.
- `mips.h` has **no** `REG_ALLOC_ORDER` => `find_reg` scans hardregs ascending (a0=4 before a1=5).
- The `pos = arg2` copy gives `pos` a hardreg copy-preference for **a1**, so `pos` always
  reclaims a1 and the preference-less const falls to a0 (the mirror of the ROM).
- The ROM's `pos`->a0 requires `arg2` to stay LIVE in a1 across `pos`'s allocation
  (non-coalesced pos/arg2). Clean liveness cannot force this here: `arg2`'s sole consumer
  `base=(s16)arg2` is scheduled to die before the loop, so nothing keeps a1 occupied.
  The ROM's `move a0,a1` is a priority/coalescing artifact (loop-frequency-weighted const
  n_refs vs. the pos-copy saving), not a liveness-forced or scheduling-misplacement fix.

## Levers tried (none flips the swap)
1. while vs if+do-while vs ternary accumulate — neutral.
2. s32 vs s16 params — s16 = the 0.5463 ceiling; s32 = 0.5073.
3. `base` from `arg2` vs from `pos` — `(s16)pos` = best; `(s16)arg2` = 0.4341 (s32) / 0.4976 (s16 base).
4. `base` before vs after loop — after-loop DOES emit `move a0,a1` (arg2 kept live) but

5. in-place accumulate into `arg2`; stmt reorder (base decl above/below pos); s16 vs s32 base;
   named `s32 end=(s16)pos` after loop; named `s32 dot=0x2E` const — all neutral or worse.
