# func_80081C90 near-match (S253 CARRY)

**Class:** `#base-register-vs-displacement` / `#indexed-vs-pointer-loop-strength-reduction` terminal
loop variant. Permuter-unreachable (addressing-mode + loop.c strength-reduction decision, not a
source permutation).

## What it does (fully RE'd)

Two 14-iteration read-modify-write loops over the fixed global array `D_800C54F2` (a u16 field,
0x10-byte struct stride; per-bank base = `sky_panel_bank_index * 448`):

```c
extern s32 wind_magnitude;   /* ghidra type is u32, but the asm does SIGNED /8192 (bltzl+sra) */
extern u16 D_800C54F2;
extern u32 sky_panel_bank_index;

void func_80081C90(void) {
  s32 delta = wind_magnitude / 8192;   /* bltzl v0; addiu v0,0x1FFF; sra a1,v0,13 */
  s32 off;
  s32 i;

  off = sky_panel_bank_index * 448;    /* (idx<<3 - idx) << 6 = idx*7*64 */
  for (i = 0; i != 14; i++) {
    *(u16*)((u8*)&D_800C54F2 + off) += delta;
    off += 0x10;
  }

  off = sky_panel_bank_index * 448;    /* re-reads the global, recomputes base */
  if (*(s16*)((u8*)&D_800C54F2 + off) >= 0x4001) {   /* lh; slti 0x4001; bnez -> skip */
    for (i = 0; i != 14; i++) {
      *(u16*)((u8*)&D_800C54F2 + off) -= 0x2000;
      off += 0x10;
    }
  }
}
```

Structure (both loops, the guards, the signed div, the base recompute, `bltzl` polarity, `slti`
guard) is byte-exact. Only the per-iteration array addressing diverges.

## The wall

- **ROM:** keeps `v1` as a PURE byte offset (init `idx*448`, `addiu v1,v1,0x10` in the branch delay
  slot) and re-materializes the base per access: `lui vX,%hi(D_800C54F2); addu vX,vX,v1; lhu/sh
  ...,%lo(D_800C54F2)(vX)` — emitted TWICE per iteration (separately for the load and the store), NO
  base hoist, NO pointer giv. ~10 instrs/iteration in loop1.
- **My build (every spelling):** gcc-2.7.2 `loop.c` strength-reduction folds `&D_800C54F2 + off` into
  ONE walking pointer hoisted before the loop (`lui;addiu;addu v1` in the preheader, then `0(v1)` for
  both load and store), `addiu v1,v1,0x10` per iter. ~6 instrs/iteration. Fewer instructions =
  genuine near-miss, not a reg-swap.

## Levers tried (all fail, all reduce to the walking pointer)

1. Byte-offset cast `*(u16*)((u8*)&D_800C54F2 + off)`, `for`, running `off += 0x10` — SR'd.
2. Same, `do { } while (i != 14)` wrapper (S235 recipe) — SR'd identically.
3. Real array `u16 D_800C54F2[]`, element index `D_800C54F2[off]`, `off += 8` — SR'd.
4. Counter-indexed symbol `D_800C54F2[base + i*8]` (S168 array-symbol form) — worse (spurious frame +
   doubled-index giv), still SR'd.

## Why terminal (distinct from the S235 crack)

The S235 `func_8006F24C` crack forced gcc into the ROM's **DEST_REG pointer giv** (`s32 *p = base+K;
*p++`). That does not apply here: this ROM uses **no pointer giv at all** — it keeps indexed
`%hi+offset+%lo` addressing and re-materializes the base per access, which gcc-2.7.2 with loop
strength-reduction ON never emits for a clean counted loop over a fixed-address array. mips.h
`GO_IF_LEGITIMATE_ADDRESS` (config/mips/mips.h:2318-2349) accepts `reg + symbol` so the ROM's
compile could keep re-materializing, but loop.c runs SR first and folds it. No `-f`-free source escape;
permuter is documented not to flip base-vs-displacement. Escalation would be a compiler-source dive
(why loop.c skipped SR on the ROM build) or corpus-mining; not worth it for one 47-instr leaf.
